正式测试流程优化方案 - RS485 两遍交叉 256CH

目标：将正式测试流程迁移为 RS485 中位机通道计划 + START，由 3562 与 34461 使用缓存方式保存测试值，测试完成后上位机一次性读取缓存，并按照 G1/G2 两遍交叉规则回填 256 个物理通道。

核心变化：两遍模式不是重复测量取均值，而是 G1/G2 交叉分工。第一遍 G1 测内阻、G2 测电压；第二遍 G1 测电压、G2 测内阻。最终每个物理通道只形成一组内阻和一组电压。

适用范围：正式测试、零星通道测试、NG 复测、校准流程可继续复用中位机通道计划能力，但正式测试的数据回填必须使用本文定义的两遍映射规则。

一、已确认的设备职责

设备职责说明
中位机 只负责通道计划和 START 通过 RS485，115200 bps，8N1 通讯。协议帧头 AA，写命令 0x06 原样回显，读命令 0x03 返回寄存器，事件帧 0x41 主动上报。
3562 内阻测试仪 设置外部触发、连续初始化、清空缓存、打开缓存。完成后一次性读取全部内阻缓存。
34461 电压测试仪 设置外部触发，并按本次预期触发数量读取一组缓存电压。
上位机 流程编排、数据读取、数据回填、判定、保存、上传 上位机不再向中位机发送选择 ACIR/OCV 的旧指令，也不再依赖旧 TCP 中位机逻辑。

二、两遍模式定义

阶段G1 物理通道G2 物理通道3562 缓存含义34461 缓存含义
第一遍 CH1-CH128 CH129-CH256 G1 内阻，即 CH1-CH128 Resistance G2 电压，即 CH129-CH256 Voltage
第二遍 CH1-CH128 CH129-CH256 G2 内阻，即 CH129-CH256 Resistance G1 电压，即 CH1-CH128 Voltage

完整 CH1-CH256 测试的缓存映射

3562[0..127]   -> CH1..CH128 Resistance
3562[128..255] -> CH129..CH256 Resistance

34461[0..127]   -> CH129..CH256 Voltage
34461[128..255] -> CH1..CH128 Voltage

非完整通道测试的映射原则

连续区间、零星通道、NG 复测都必须先按物理通道拆分为 G1/G2：

G1PhysicalChannels = selected channels where 1 <= ch <= 128
G2PhysicalChannels = selected channels where 129 <= ch <= 256
G2LocalChannels = G2PhysicalChannels - 128

两遍模式下，仪表缓存不是简单等于用户选择顺序，而是按组和遍次回填：

First pass:
  3562 values -> G1PhysicalChannels Resistance
  34461 values -> G2PhysicalChannels Voltage

Second pass:
  3562 values -> G2PhysicalChannels Resistance
  34461 values -> G1PhysicalChannels Voltage

已确认：中位机两遍模式允许某一组为空。两台仪表触发次数不要求永远相同；对上位机来说，只要正确设定 G1 和 G2 的目标通道即可。缓存数据的回填顺序按每组物理通道号升序排列，不按用户点击顺序。

G1PhysicalChannels = sort ascending(G1 selected physical channels)
G2PhysicalChannels = sort ascending(G2 selected physical channels)

3562 resistance order:
  first G1PhysicalChannels ascending
  then  G2PhysicalChannels ascending

34461 voltage order:
  first G2PhysicalChannels ascending
  then  G1PhysicalChannels ascending

三、目标正式测试流程

  1. 点击开始测试。
  2. 检查报警状态；报警时禁止测试。
  3. 初始化测试状态：清空报警显示，设置 isRuning=True，读取起始通道和结束通道，初始化 256 通道 RecieveData，检查托盘号，防止空托盘号或重复托盘号误测。
  4. 判断本次是 OCV0、OCV1、OCV2。
  5. 检查中位机串口通讯：RS485，115200，8N1。串口来源使用 frmInit 设置。
  6. 夹具动作：查询托盘状态、夹具下压、等待约 9 秒、确认夹具闭合。夹具后续由 PLC 实现，本轮先封装边界，避免继续扩散旧中位机 TCP 逻辑。
  7. 探针寿命计数加 1。
  8. 配置 3562：外部触发、连续初始化、清空缓存、打开缓存。
  9. 配置 34461：外部触发、清空缓存、设置触发数量、准备缓存读取。
  10. 根据正常测试、零星测试或 NG 复测生成通道计划。通道列表必须按物理通道号升序组织。
  11. 下发计划前清空 3562 和 34461 缓存。
  12. 确认 3562 和 34461 已进入外部触发等待状态。
  13. 中位机执行通道计划并 START。
  14. 等待中位机完成事件 AA 41 00 40 00 06 A5 C8，并轮询基础状态寄存器进行双确认。收到异常事件 AA 41 00 40 00 64 24 21 时停止测试。
  15. 读取 3562 缓存。
  16. 读取 34461 缓存。
  17. 按两遍交叉映射规则回填 RecieveData(ch).Resistance 和 RecieveData(ch).Voltage。内阻叠加 calibrateValueArray(ch) 校准值。
  18. 刷新 256 通道电池界面。
  19. 测试结束后松开托盘。
  20. 调用 IsNG(voltage, resistance) 判断 OK/NG。NG 点写入 retestArray。
  21. 保存本地 CSV：D:\OcvTestData\日期\托盘号.csv。
  22. 如 MES 上传勾选，则启动结果上传。
  23. 写数据库：已有记录则更新，没有则插入。
  24. 如果发现 NG 点，询问是否执行 NG 复测；确认后按 retestArray 生成零星通道计划。NG 复测后只覆盖 NG 点，未复测通道保持初测结果。

四、必须补齐的设计细节

项目必须明确的规则原因
缓存数量 两遍模式下，3562 和 34461 的实际触发次数可以不同。上位机按本次 G1/G2 指定通道构建各仪表的期望读取数量；完整 256CH 时每台仪表各 256 条。 中位机允许某一组为空，且两组长度可以不同，不能把仪表触发次数写死为固定值。
通道映射 正式测试不直接使用单一 ExecutionOrder 回填全部数据，而使用 G1PhysicalChannels、G2PhysicalChannels、遍次和仪表类型组合回填。 单一顺序会在两遍交叉模式下导致电压/内阻错填。
零星通道 零星通道先拆分 G1/G2。G2 下发前转换为本地 CH1-CH128，回填时恢复为物理 CH129-CH256。 中位机按本地组内通道执行，上位机保存必须使用物理通道号。
两组长度不同 缓存顺序按每组物理通道号升序排列。G1/G2 列表长度不同不影响回填，只要上位机保存的是排序后的 G1/G2 通道列表。 用升序通道列表作为缓存和物理通道之间的唯一映射依据，避免用户选择顺序造成错填。
串口收发 每条 0x06 等待原样回显。写配置后必须读取 0x005B~0x005D 判断写入结果、最后写入地址和配置锁状态。 写命令回显只代表收到，不代表执行成功。
状态确认 START 后正式流程轮询基础状态 AA 03 00 40 00 07 1C 07，完成事件与状态寄存器双确认。 状态读取成为正式流程的一部分，提高现场抗干扰能力。
事件过滤 START 前清空串口接收缓冲；等待事件时只接受本轮 START 之后的新 0x41 完成/异常事件。 避免旧完成事件造成误判。
异常收尾 异常或超时时必须 STOP、清 G1/G2 通道列表、清理仪表触发/缓存状态、恢复 isRuning=False、记录日志、避免下轮沿用旧缓存。 实机故障后最怕状态脏，下一次测试数据会污染。
缓存时序 下发中位机计划前清仪表缓存；START 前确认仪表已进入等待触发状态；完成后先读取仪表缓存，再允许下一次测试初始化；异常时也清缓存。 缓存清理和读取顺序必须固定，否则可能读到上一盘残留数据。
校准单位 calibrateValueArray(ch) 按 mΩ 保存。3562 读取值进入 RecieveData 前也必须统一为 mΩ，再叠加校准值。 避免 Ω 与 mΩ 混用导致结果放大或缩小 1000 倍。
NG 复测覆盖 NG 复测只覆盖 NG 点。CSV、数据库、MES 上传均应使用覆盖后的最终结果；未复测通道保持初测结果。 保证界面、文件、数据库和 MES 的最终数据一致。
互斥访问 正式测试、校准、调试手动动作之间必须互斥访问中位机和仪表。 避免串口和仪表命令交叉。
校准/正式测试映射隔离 校准页面继续使用 ChannelCalibrationRunner；正式测试使用 TwoPassResultMapper。不要把两遍交叉映射套到校准流程。 两者虽然共用中位机通道计划，但数据来源和回填含义不同。
256 通道界面 全局变量已调整为 Public Const intRow As Int16 = 16、Public Const intCol As Int16 = 16。本方案不再单独修改界面布局。 界面 16x16 显示由全局变量处理，当前优化聚焦测试主流程和数据正确性。

六、实施计划

Task 1：建立通道选择模型

  • 新增 TestChannelPlanService.vb。
  • 实现 BuildRangeSelection(startChannel, endChannel)。
  • 实现 BuildSparseSelection(channels)。
  • 实现 BuildRetestSelection(retestArray)。
  • 输出对象必须包含 SelectedPhysicalChannels、G1PhysicalChannels、G2PhysicalChannels、G2LocalChannels、ExpectedHiokiCount、ExpectedDmmCount。
  • G1PhysicalChannels 和 G2PhysicalChannels 必须按通道号升序排列，允许任意一组为空。
G1PhysicalChannels = sort ascending(channels where 1 <= ch <= 128)
G2PhysicalChannels = sort ascending(channels where 129 <= ch <= 256)
G2LocalChannels = G2PhysicalChannels - 128

ExpectedHiokiCount = G1PhysicalChannels.Count + G2PhysicalChannels.Count
ExpectedDmmCount = G2PhysicalChannels.Count + G1PhysicalChannels.Count

Task 2：建立两遍映射器

  • 新增 TwoPassResultMapper.vb。
  • 输入：通道选择模型、3562 内阻数组、34461 电压数组、校准数组。
  • 校验：3562 返回数量必须不小于 ExpectedHiokiCount，34461 返回数量必须不小于 ExpectedDmmCount。
  • 回填规则：3562 按 G1 升序内阻、G2 升序内阻；34461 按 G2 升序电压、G1 升序电压。
  • 内阻回填前确认 3562 值单位为 mΩ，再叠加同样为 mΩ 的 calibrateValueArray。
For i = 0 To G1PhysicalChannels.Count - 1
    ch = G1PhysicalChannels(i)
    RecieveData(ch - 1).Resistance = hiokiResistance(i) + calibrateValueArray(ch - 1)
Next

For i = 0 To G2PhysicalChannels.Count - 1
    ch = G2PhysicalChannels(i)
    RecieveData(ch - 1).Resistance = hiokiResistance(G1PhysicalChannels.Count + i) + calibrateValueArray(ch - 1)
Next

For i = 0 To G2PhysicalChannels.Count - 1
    ch = G2PhysicalChannels(i)
    RecieveData(ch - 1).Voltage = dmmVoltage(i)
Next

For i = 0 To G1PhysicalChannels.Count - 1
    ch = G1PhysicalChannels(i)
    RecieveData(ch - 1).Voltage = dmmVoltage(G2PhysicalChannels.Count + i)
Next

Task 3：补齐仪表缓存读取闭环

  • 复核 Trans_ReadCachedData_3562(expectedCount, voltages, resistances) 的单位和返回顺序。
  • 新增或修正 Trans_ReadCachedData_34461(expectedCount, voltages)。
  • 每次下发中位机计划前清空两台仪表缓存。
  • START 前确认两台仪表均已进入外部触发等待状态。
  • 完成后先读取两台仪表缓存，再允许下一次测试初始化。
  • 异常时清空两台仪表缓存。
  • 读取后记录期望数量、实际数量、原始返回摘要。

Task 4：增强中位机串口闭环

  • START 前清空串口接收缓冲。
  • 每条写命令校验原样回显。
  • 关键配置写入后必须读取 0x005B~0x005D。
  • START 后轮询基础状态 AA 03 00 40 00 07 1C 07。
  • 等待完成事件 0x0006，异常事件 0x0064 立即失败。
  • 超时或异常时发送 STOP，并清空 G1/G2 通道列表。

Task 5：新增正式测试 Runner

  • 新增 FormalTestRunner.vb。
  • 实现 RunTwoPassMeasurement(selection)。
  • 流程为：准备 3562、准备 34461、下发中位机计划、START、等待完成、读取两台仪表缓存、调用 TwoPassResultMapper。
  • 失败时执行统一收尾：STOP、清缓存或复位触发状态、记录日志、抛出明确错误。

Task 6：重构 frmTest.StarTest

  • 保留报警检查、托盘号检查、OCV0/1/2 判断、探针寿命、保存、MES、数据库、NG 复测入口。

  • 删除 IOCardSetAcirOrOcv("ACIR")、IOCardSetAcirOrOcv("OCV") 和选择 ACIR/OCV 仪表的中位机指令。
  • 根据正常范围、零星选择或 NG 复测构建通道选择模型。
  • 调用 FormalTestRunner.RunTwoPassMeasurement 完成测试。

Task 7：扩展 256 通道保存、刷新、复测

  • 把 testData(63)、ReDim retestArray(63)、For i = 0 To 63 等固定 64 通道逻辑改为 256。
  • 确认 CSV 输出 256 个物理通道。

  • 如果当前界面只能显示 64 点，至少数据层先完整保存 256 点，界面显示作为单独 UI 优化项。
