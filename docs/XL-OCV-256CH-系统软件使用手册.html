1. 使用范围

本手册用于操作员、设备工程师和维护人员使用 XL-OCV-256CH 系统，覆盖托盘识别、256 通道电芯条码加载、正式 OCV 测试、PLC 联动、本地保存、MES 后台上传和 NG 复测。

版本说明：本手册以最新的自动测试状态机流程为准。自动测试的主入口是托盘状态机，不再使用旧的 autoStartFlag + Timer4 直接触发 StarTest(1)。
安全原则：托盘码、电芯条码或托盘压合状态任一项不满足时，系统不得调用正式测试入口，也不得向 PLC 发送“测试完成”。

2. 启动前检查

  1. 确认测试电脑、PLC、扫码器、中位机、3562 内阻仪和 34461A 电压仪已通电。
  2. 确认测试软件以正确用户登录；参数设置、测试上下限和工位选择与当前产品匹配。
  3. 确认 PLC 通讯模式、地址和托盘压合地址已配置；旧配置文件缺少压合地址时，自动模式不可用。
  4. 确认 MES 数据库配置完整，网络可访问。
  5. 确认夹具处于安全状态，没有急停、烟感、超温等报警。
  6. 首次开机或更换设备后，在调试/状态页面逐项确认设备连接状态。
建议：生产前先用一盘已在 MES 完整建档的托盘做小范围验证，确认扫码、条码查询、压合状态和结果保存链路均正常，再进入连续生产。

4. 自动模式与手动模式对照

项目自动模式手动模式
OCV 阶段设备运行前固定设置 OCV0、OCV1 或 OCV2；测试启动时不再弹窗确认阶段，配置无效时禁止启动。
启动方式PLC 检测托盘到位并稳定后自动启动流程。操作员点击“启动测试”。
托盘码来源扫码成功后写入 txtTray，再从控件读取。操作员直接输入或粘贴到 txtTray。
电芯码加载扫码后按托盘码重新查询。256 通道全测；空位只保留测量，不写正式电芯结果。点击“启动测试”后按托盘码重新查询；所选通道必须都有电芯码。
压合检查等待 R151 从低到高。未压合或 PLC 读取失败时弹框并停止。
正式测试条件满足后自动调用一次 StarTest(1)。前置检查全部成功后调用 StarTest(1)。
PLC 完成通知测试结果保存后发送 R161；需要 NG 分选的阶段随后等待 R152，只发送最终 NG 档位 2 到 DT1001～DT1256 对应地址，再发送 R162。合格电池不写 DT。手动测试不发送自动流程完成通知。
MES 上传均使用测试结果快照后台上传，不阻塞主测试流程。

5. 自动模式操作流程

1选择自动
→
2托盘到位稳定
→
3读取 R150 并扫码
→
4码无效时手工输入
→
5准备托盘并发送 R160
→
6R151=1 时开始测试

5.1 状态说明

WaitingForTray等待托盘到位。
TrayDetected托盘到位已稳定。
Scanning正在读取扫码结果；失败或长度不符时进入手工输入。
LoadingCellBarcodes按托盘码查询和校验电芯码。
ReadyToTest条码已准备，等待最终设备检查。
WaitingForClamp等待 PLC 确认托盘压合。
Testing执行正式 OCV 测试。
SavingLocalResult保存本地测试结果。
WaitingR151收到 R160 后等待 PLC 的测试启动信号。
WaitingR152测试结果保存并发送 R161 后，等待排不良位信号。
SendingNgGrades只发送最终 NG 档位 2，全部确认后发送 R162。
Completed本轮完成，等待托盘离开。
Error本轮异常，处理后重新开始。

5.2 操作员需要注意

  • 同一托盘在未离开前不会重复扫码、重复查询或重复启动测试。
  • 扫码成功后，主页面的 txtTray 应显示本次托盘码；显示为空代表流程不能继续。
  • 查询成功但夹具未压合时，界面显示“等待托盘压合”，不会弹出阻塞式确认框，也不会开始测试。
  • 等待压合期间托盘离位，本轮自动任务取消，系统回到等待下一托盘状态。
  • 正式测试完成后，由 PLC 安排松夹具、放行和下一步动作，上位机不自行安排机械流程。

6. 手动模式操作流程

  1. 选择“手动”。
  2. 在 txtTray 输入托盘码。
  3. 点击“启动测试”。
  4. 系统检查托盘码是否为空；为空时提示并结束。
  5. 系统按托盘码重新查询电芯条码，校验所选通道均有有效电芯码。
  6. 系统读取 PLC 托盘压合状态。
  7. 确认压合后，将本次数据装载到测试执行缓存并调用 StarTest(1)。
  8. 测试完成后保存结果，MES 上传在后台执行。
禁止事项：所选通道缺少电芯码、PLC 无法读取或托盘未压合时不能继续测试；每次启动都会清除上一托盘的条码缓存。

7. 托盘码查询电芯码

7.1 查询关系

txtTray 托盘码
    ↓ 参数化查询
MES 数据库 batcode
    ↓ 返回 ChannelNo + BatteryCode
1～256 通道电芯条码字典
    ↓ 完整性校验
测试周期上下文 / 测试执行缓存
    ↓
StarTest(1)

数据库查询使用托盘码参数，不使用字符串拼接。正式测试要求完整返回 1～256 通道数据，即使本次手动只选择部分通道，也必须先确认托盘基础数据完整。

7.2 查询失败处理

失败情况界面/流程处理操作员处理
托盘码为空不访问数据库，不开始测试。重新输入或重新扫码。
托盘码不存在判定为无数据/数据不完整，不调用 StarTest。确认托盘码，确认 MES 是否已经建档。
少于 256 条或缺少通道提示缺失通道，不装载部分数据。补齐 MES 数据后重新查询。
通道非法或重复查询校验失败，不开始测试。修正数据库基础数据。
电芯码为空或重复查询校验失败，不开始测试。检查电芯条码绑定关系。
数据库配置不完整提示 MES 数据库配置错误。由工程师检查服务器、数据库、账号、密码。
网络、连接或 SQL 异常查询异常，不保存结果、不通知 PLC。检查网络和数据库服务后重试。
安全边界：查询失败时不会调用 StarTest(1)，不会保存本轮正式结果，也不会发送 PLC 测试完成信号。

8. 结果保存、MES 上传与 PLC 通知

测试/复测完成形成最终结果
→
保存结果OCV_DATA / 本地文件
→
测试完成发送 R161 并等待 ACK
→
需分选时等待 R152=1
→
NG 交接仅写 NG=2，再发送 R162

MES 上传是旁路任务：

本地保存成功
    ├── 自动各阶段：最终测试结果保存后发送 R161
    ├── 需要 NG 分选的阶段：等待 R152=1，只向最终 NG 对应 DT 写入档位 2
    │                       所有 NG 写入确认后发送 R162
    ├── R162 获得确认后：释放本托盘状态；新托盘仍须完成 R150/R160 才会读取 R151
    └── 后台：将不可变结果快照加入 MES 上传队列

MES 上传失败 → 记录失败 → 使用同一任务快照和幂等键重试
结果环节失败时处理
测量失败不认定为完成，不通知 PLC 完成。
本地保存失败不通知 PLC 完成；保留任务信息，允许人工处理。
等待 R152=1测试结果已保存且 R161 已发送；暂不写 DT、不发送 R162，也不启动下一托盘流程。
NG DT 写入失败保留当前最终 NG 集合并重试；没有全部确认前不发送 R162。
R162 ACK 超时只重试 R162，不重新测试、保存结果或重复写档位。
MES 上传失败不阻塞已完成的本地流程和 PLC 放行，进入后台重试。
R161 ACK 超时不重新测量或保存结果；只重试测试完成通知。

客户定义的 PLC 挑选地址按逻辑序号顺序对应：NG 序号 n 写入 DT(1000+n)，例如序号 1→DT1001、序号 2→DT1002、序号 256→DT1256。该地址序列不表示电池在托盘中的实际坐标，也不使用托盘行列转置映射。

需要分选的阶段在测试结果保存并发送 R161 后等待 R152=1。上位机只对复测后的最终 NG 序号写入档位 2，合格序号不写。所有 NG 写入收到确认后才发送 R162；R162 确认前不会开始下一托盘流程，也不会读取下一次 R151。

上位机不向合格地址写 0。PLC 需在下一托盘交接前按设备时序清除旧 DT 挑选数据；该清除行为需通过现场 PLC 程序和连续多托盘联调确认。OCV 阶段不需要 NG 分选时，跳过 R152、DT 和 R162。

9. NG 复测

  1. 正式测试完成后查看 NG 通道。
  2. 确认托盘仍在位且已压合。
  3. 选择需要复测的 NG 通道。
  4. 点击“NG点测试”，执行 StarTest(0)。
  5. 复测结果单独保存并后台上传 MES。
复测边界：复测不会重新扫码，不重新创建自动 PLC 完成任务，也不会替代已经通知 PLC 的正式测试完成状态。复测不能与新的正式测试并发执行。

10. 系统配置

10.1 PLC 通讯和自动流程地址

配置项含义要求
PLC 通讯方式Modbus TCP 或 Modbus RTU/COM。必须与现场 PLC 接口一致。
托盘到位地址判断托盘是否进入工位。不能代替压合地址。
托盘压合地址判断夹具是否已压合。必须单独配置，不能默认为地址 0。
测试允许地址PLC 是否允许上位机开始测试。自动模式使用。
测试完成命令地址上位机通知 PLC 测试完成。由 PLC 点位表确认。
完成 ACK 地址PLC 确认收到完成通知。用于完成握手和重试。
稳定采样/离位采样避免单次信号抖动导致重复启动或误结束。按现场信号质量调整。

10.2 MES 数据库

  • 配置 MES 数据库服务器、数据库名、用户名和密码。
  • 确认托盘码与 1～256 通道电芯码已在 MES 中完成绑定。
  • 同一托盘的通道号和电芯码不能重复。
  • 修改配置后重新启动或重新加载设置，避免继续使用旧连接参数。

11. 异常处理

现象优先检查恢复方式
自动模式不可用PLC 自动流程地址是否完整，尤其是托盘压合地址。补齐配置并重新启动流程。
一直等待托盘托盘到位信号、PLC 通讯、传感器和工位位置。确认托盘实际到位并重新观察状态。
扫码失败扫码器串口、扫码距离、条码质量、托盘在位状态。重新扫码；必要时切换手动模式输入托盘码。
查不到电芯码托盘码是否正确、MES 是否建档、网络和数据库连接。修正数据或配置后重新查询，禁止使用旧数据测试。
等待托盘压合夹具机械状态、托盘压合地址、PLC 点位映射。压合托盘；不要强行点击启动测试。
测试完成但 PLC 未继续本地保存状态、完成通知队列、PLC ACK 地址和通讯。查看通知日志并重发同一任务，不要重测。
MES 上传失败MES 网络、接口地址和后台队列。保留本地结果，恢复网络后等待后台重试。
报警或急停现场安全状态、急停、烟感、温度和夹具。排除现场故障并复位报警，再重新执行前置检查。
不要这样处理：不要通过重复点击启动、直接改写条码、跳过压合检查、重测来代替 PLC 完成通知，或删除本地结果文件来“清除”失败。

12. 操作员检查表

每盘测试前

  • □ 当前模式正确：自动或手动。
  • □ 托盘码已正确识别/输入。
  • □ 电芯条码查询成功且数据完整。
  • □ 托盘已到位并完成压合。
  • □ 无报警，仪表和 PLC 通讯正常。
  • □ 手动模式已选择正确测试通道。

每盘测试后

  • □ 已生成本地测试结果。
  • □ 自动模式已看到 PLC 完成通知/应答状态。
  • □ MES 上传任务没有持续失败。
  • □ NG 通道已记录；需要时单独执行复测。
  • □ PLC 已安排下一步动作，未人工重复操作夹具。

维护人员验收顺序

  1. 验证空托盘码不会访问数据库或启动测试。
  2. 验证托盘码无记录、部分条码、重复条码都会阻止测试。
  3. 验证托盘未压合时自动模式保持等待，手动模式弹框停止。
  4. 验证本地保存成功后 PLC 能收到完成通知。
  5. 断开 MES 网络，确认本地保存和 PLC 流程不被阻塞。
  6. 模拟 PLC ACK 超时，确认重发通知而不是重新测量。
  7. 验证复测不会重新触发自动 PLC 完成流程。
