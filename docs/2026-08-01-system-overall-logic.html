XL-OCV-256CH 系统整体逻辑说明

文档目的：说明当前系统在完成 RS485 中位机、G1/G2、两遍交叉测试、256 通道和校准页面优化后的整体运行逻辑。

当前定位：上位机负责业务流程、仪表配置、数据读取、数据映射、判定、保存和上传；中位机只负责通道计划和 START；3562 与 34461 负责按外部触发缓存测试值。

生成日期：2026-08-01。

一、系统分层

层级主要文件/对象职责
窗体业务层 frmTest.vb、FrmChannelCalibration.vb、frmInit.vb 处理按钮、界面状态、托盘号、OCV 选择、报警提示、测试启动、校准页面和参数设置。
正式测试编排层 FormalTestRunner.vb 准备 3562/34461 缓存，运行中位机计划，读取仪表缓存，并调用两遍映射器回填数据。
通道计划层 TestChannelPlanService.vb 把连续通道、零星通道或 NG 复测点转换成 G1/G2 升序通道列表和中位机计划。
数据映射层 TwoPassResultMapper.vb 按两遍交叉规则把 3562 内阻缓存和 34461 电压缓存回填到 RecieveData。
中位机通讯层 SerialMiddleMachineClient.vb RS485 串口协议、CRC、写回显、读寄存器、事件帧、STOP/START、G1/G2 通道计划、日志。
仪表通讯层 Module1.vb 3562 串口通讯、34461 VISA 通讯、缓存准备、缓存读取、全局数据结构和上下限判定。
数据持久化/上传层 frmTest.vb、clsDB.vb、MES 上传类 本地 CSV 保存、数据库插入/更新、MES 上传触发。

二、核心全局数据

变量/结构含义说明
MAX_CHANNEL = 256 系统通道总数 当前项目按 256 个物理通道运行。
intRow = 16、intCol = 16 界面点位布局 16 x 16 显示 256 个点位。
RecieveData(0..255) 正式测试结果缓存 数组下标为 0-based；物理 CH1 对应 RecieveData(0)，CH256 对应 RecieveData(255)。
retestArray(0..255) NG 复测标记 值为 1 表示该物理通道需要复测；下标 0 对应 CH1。
calibrateValueArray 内阻校准补偿值 单位为 mΩ。正式测试回填内阻时：3562 测量 mΩ + 校准 mΩ。
Initsetting.SCMComPort、Initsetting.SCMComRate 中位机串口参数 由 frmInit 设置。默认通讯为 RS485、115200、8N1。

三、正式测试总流程

  1. 用户点击开始测试，入口为 CmdStart_Click。
  2. 如果处于报警状态，直接禁止测试。
  3. 调用 StarTest(1) 启动正常测试；NG 复测时调用 StarTest(0)。
  4. 清空报警显示，刷新界面状态，设置 isRuning=True。
  5. 读取起始通道、结束通道，计算本次通道数量。
  6. 正常测试时初始化 256 个 RecieveData 的电压、内阻、测试时间。
  7. 检查托盘号：空托盘号禁止测试；与上次托盘号相同则提示确认。
  8. 判断 OCV 轮次：当前仍由 Rbtn1~Rbtn4 映射到 OCV 序号。
  9. 通过 CheckCom_SCM() 检查中位机串口通讯，并同步全局 Com_SCM。
  10. 执行夹具动作：当前仍保留旧夹具逻辑，后续将由 PLC 替换。
  11. 探针寿命计数加 1，并刷新剩余次数。
  12. 禁用托盘手动控制按钮，进入测试中状态。
  13. 调用 FormalTestRunner 执行正式测量。
  14. 测量完成后刷新电池界面，松开托盘。
  15. 调用 IsNG(voltage, resistance) 判定 OK/NG。
  16. 保存本地 CSV。
  17. 如 MES 上传勾选，则触发 MES 结果上传。
  18. 写数据库：已有记录更新，无记录插入。
  19. 如发现 NG 点，询问是否执行 NG 复测；确认后调用 StarTest(0)。
  20. 退出时恢复托盘按钮、鼠标状态，并设置 isRuning=False。

四、正式测量编排逻辑

正式测量由 FormalTestRunner 完成，窗体不再直接发送旧 TCP 多通道测试指令，也不再切换 ACIR/OCV 仪表选择。

StarTest
  -> FormalTestRunner.RunRangeMeasurement(startChannel, endChannel)
     or FormalTestRunner.RunRetestMeasurement(retestArray)
  -> TestChannelPlanService 生成通道选择模型
  -> 清 3562/34461 缓存
  -> PrepareCachedData_3562
  -> PrepareCachedData_34461
  -> SerialMiddleMachineClient.RunPlan
  -> Trans_ReadCachedData_3562
  -> Trans_ReadCachedData_34461
  -> TwoPassResultMapper.Apply
  -> RecieveData 完成回填

仪表缓存时序

  1. 下发中位机计划前，先清理 3562 和 34461 的缓存/缓冲。
  2. 3562 设置为外部触发、连续初始化、清空缓存、打开缓存。
  3. 34461 设置为外部触发，设置触发次数，并通过 READ? 进入等待触发状态。
  4. 中位机执行通道计划并 START。
  5. 中位机上报完成后，上位机读取 3562 缓存。
  6. 上位机读取 34461 缓存。
  7. 任何异常都会尝试 STOP、清 G1/G2 列表，并清理仪表缓存。

五、G1/G2 与两遍模式

组别物理通道中位机本地通道
G1 CH1-CH128 CH1-CH128
G2 CH129-CH256 物理通道 - 128，即 CH129 对应本地 CH1，CH256 对应本地 CH128

两遍交叉含义

阶段G1G23562 数据34461 数据
第一遍 切换 G1 目标通道 切换 G2 目标通道 G1 内阻 G2 电压
第二遍 切换 G1 目标通道 切换 G2 目标通道 G2 内阻 G1 电压

缓存回填顺序

通道选择模型会把通道去重并按物理通道号升序排列。缓存按每组升序回填，不按用户点击顺序。

3562 resistance:
  first  -> G1PhysicalChannels ascending
  second -> G2PhysicalChannels ascending

34461 voltage:
  first  -> G2PhysicalChannels ascending
  second -> G1PhysicalChannels ascending

示例：选择 CH3、CH8、CH25、CH129：

G1PhysicalChannels = [3, 8, 25]
G2PhysicalChannels = [129]
G2LocalChannels = [1]

3562[0] -> CH3   Resistance
3562[1] -> CH8   Resistance
3562[2] -> CH25  Resistance
3562[3] -> CH129 Resistance

34461[0] -> CH129 Voltage
34461[1] -> CH3   Voltage
34461[2] -> CH8   Voltage
34461[3] -> CH25  Voltage

六、中位机通讯逻辑

项目当前逻辑
通讯参数 RS485，115200 bps，8N1。端口和波特率来自 Initsetting.SCMComPort、Initsetting.SCMComRate。
帧格式 帧头 0xAA；写命令 0x06；读命令 0x03；事件帧 0x41。
CRC CRC16-Modbus，低字节在前。
写命令 发送后等待 8 字节原样回显；提供 WriteRegisterAndVerifyStatus 用于写后读取 0x005B~0x005D。
每次运行计划 先 STOP，再清 G1/G2 列表，配置模式和通道，配置两遍、四项全测、稳定档，复核寄存器，然后 START。
完成判断 等待事件 0x41，状态 0x0006 表示完成；状态 0x0064 表示异常。
异常处理 异常或超时会尝试 STOP，并清 G1/G2 通道列表。
日志 写入 Application.StartupPath\logFile\MiddleMachine_yyyyMMdd.log。

七、OK/NG 判定和复测

  1. 测试完成后，正式测试按起始通道到结束通道逐点判定。
  2. NG 复测时只遍历 retestArray(i)=1 的通道。
  3. 判定函数为 IsNG(voltage, resistance)。
  4. 电压以 V 保存到 RecieveData(ch).Voltage，判定时乘以 1000 与 mV 上下限比较。
  5. 内阻以 mΩ 保存到 RecieveData(ch).Resistance，直接与 mΩ 上下限比较。
  6. NG 复测只覆盖 NG 点，未复测通道保留初测结果。

八、数据保存、数据库和 MES

环节当前逻辑
本地 CSV 保存到 D:\OcvTestData\日期\托盘号.csv；当前保存数组已扩展为 256 个通道。
文件重名 如果同名文件存在，自动生成 托盘号_1.csv、托盘号_2.csv 等。
数据库 按通道遍历，查询电芯记录；存在则更新，不存在则插入。
MES 如果 FrmMesTask.chkResultDataUploadAssembly 勾选，则启动上传计时器。

九、校准逻辑

  1. 校准入口已独立为菜单项“校准”和独立 256 通道校准页面。
  2. 校准页面使用 ChannelCalibrationRunner，不使用正式测试的 TwoPassResultMapper。
  3. 校准可以全选、范围选择、单通道或部分通道选择。
  4. 校准值保存到 CalibrateArr.csv，并加载到 calibrateValueArray。
  5. 标准阻值会保存到配置中，下次打开窗体时使用上次修改值。
  6. 校准完成后自动保存校准值。
  7. 注意：校准和正式测试虽然都可复用中位机通道计划，但数据映射规则不同。正式测试是两遍交叉，校准不是。

十、当前仍保留/待后续替换的部分

项目当前状态后续方向
夹具动作 正式测试中仍保留旧夹具下压、托盘状态、松开托盘逻辑。 后续按 PLC 通讯方案替换。
调试/手动旧函数 frmTest.vb 中仍有旧的 Trig34461、部分旧 TCP 调试函数。 正式测试主路径已不调用；后续可分批清理。
OCV 序号 界面仍有 Rbtn1~Rbtn4，当前逻辑映射到 OCV1~OCV4。 如果现场只使用 OCV0/OCV1/OCV2，需要再统一 UI 和数据库字段定义。
34461 缓存命令 当前封装为 READ? 后 ReadList。 需要实机确认 34461 外触发缓存数量、返回顺序和超时设置。
写后状态寄存器 已提供 WriteRegisterAndVerifyStatus，但普通 RunPlan 的大部分写命令仍使用原样回显校验。 后续可把关键配置写入统一切到写后读取 0x005B~0x005D。

十一、运行状态和日志

  • 测试运行标志：isRuning。
  • 正式测试日志：logFile\LogOfRun.txt。
  • 中位机通讯日志：logFile\MiddleMachine_yyyyMMdd.log。
  • 异常时窗体会写入 txtAlarm，并弹窗提示。
  • 退出测试流程时会恢复托盘按钮和鼠标状态。

十二、建议的实机检查顺序

  1. 确认 frmInit 中中位机串口号和 115200 波特率保存正确。
  2. 单独验证中位机 STOP、清列表、连续计划、列表计划、START、完成事件。
  3. 验证 3562 外触发缓存：清缓存、触发数量、MEMory:DATA? 返回数量。
  4. 验证 34461 外触发缓存：READ? 后 ReadList 返回数量。
  5. 测试 CH4-CH8，只覆盖 G1。
  6. 测试 CH151-CH152，只覆盖 G2。
  7. 测试 CH3、CH8、CH25、CH129 跨组零星通道。
  8. 测试 CH1-CH256 完整两遍交叉。
  9. 验证 NG 复测只覆盖 NG 点。
  10. 检查 CSV、数据库、MES 是否都使用最终覆盖后的数据。
