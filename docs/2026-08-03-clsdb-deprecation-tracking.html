3.1 死代码删除

-- MDIForm.vb 行 197-201
'If CheckTcp_MES() = 1 Then

'Else

'R2-15: myClsDB 已随 clsDB 一起淘汰,Dispose 死代码删除 (数据库生命周期由 OcvDataService 每次 Using 管理)
mSock = frmDebug.mSock
为什么这是个真 bug:
  • myClsDB 在 MDIForm 整个文件内从未声明(无 Dim myClsDB、无 New),触发 BC30451 编译错误。
  • 运行时,VB.NET 实例方法的 Dispose 调用会让编译器把 myClsDB 解析为 MyClass.clsDB(模块级如有的话) — 该模块级字段不存在,所以结果是 NullReferenceException。
  • 之所以没被发现,是因为它位于 MDIForm_Load 中被外层 On Error Resume Next(如果存在)或后续 try/catch 吞掉,但仍然每次启动都跑一遍异常路径。
为什么 R2-15 后这行不该存在:
  • 旧 clsDB 模式 = 长生命周期 SqlConnection + 模块级标志位 myConnection + 单例 myClsDB。
  • 新 OcvDataService 模式 = 每次调用 Using connection As New SqlConnection(...),自动释放,无单例。
  • 因此整个项目已经不存在需要 Dispose 的数据库对象,myClsDB.Dispose() 实质上是在清理一个已经被清理过的对象。

4. 迁移原则

  1. 新代码不再使用 clsDB。统一 Using service As New OcvDataService() + 存储过程调用。
  2. 跨方法调用需要长连接的情形:
    • 不要重新引入 myClsDB 这种名字,直接新定义 Private ocvService As New OcvDataService() (重 Using of the same connection via 内部方法)。
    • 更佳:在 UI 层每次都 Using,把跨方法逻辑下沉到 OcvDataService 的高层方法里。
  3. 存储过程优先:R2-15 已交付 21 个核心存储过程,任何新 SQL 都先看 docs/sql/002_create_core_procedures.sql。
  4. 仍走 clsDB 的方法:在迁移前保留 Obsolete 警告,避免新代码被引入。
