# PLC 独立寄存器处理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 让 R150、R151、R152 各自采集和触发职责；R152 按其到达时的测试状态决定立即回 R162、等待最终结果，或发送最终 NG 档位后回 R162。

**Architecture:** 保留单一 PLC 串口轮询器，避免并发收发破坏串口协议；每轮分别读取三个输入寄存器并记录独立请求。处理输入前先捕获 R152 对应的测试状态快照，再执行托盘、测试和分选动作，避免同一轮处理顺序改变 R152 的语义。PLC 输入位 R150/R151/R152 只读；上位机只写 R160/R161/R162 和 NG 档位数据。

**Tech Stack:** VB.NET 4.8、WinForms、现有 `PlcAutomaticTestCoordinator`、`IPlcAutomationClient`、CShop ASCII PLC 协议。

---

## 代码边界

- 修改 `PlcAutomaticTestCoordinator.vb`：独立读取与缓存请求、捕获 R152 到达时状态、推进各自动作、流程事件日志和写入重试。
- 修改 `PlcAutomaticTestState.vb`：为 R152 请求增加明确的状态快照类型或等价的枚举/字段，并维护本轮最终 NG 集合及完成标记。
- 不修改 `PlcAutomationClient.vb` 与 `PlcAutomationProtocol.vb`：现有读写入口和帧格式保持不变；上位机不得增加 R150/R151/R152 写入。
- 不修改主页面布局和串口参数；本次只调整自动流程协调逻辑。

## 状态与规则

R152 捕获时记录以下快照：

| 快照状态 | 动作 |
|---|---|
| 未开始测试 | 本轮没有测试产生的 NG 档位；跳过 DT 写入，直接写 R162=1 |
| 测试进行中（包括 NG 复测） | 保存 R152 请求；最终结果发布并且 R161 确认后，写最终 NG 档位，再写 R162=1 |
| 测试已完成 | 读取本轮最终 NG 集合；有 NG 就按顺序写档位，无 NG 就跳过；最后写 R162=1 |
| 测试执行异常 | 不把不完整结果当作“无 NG”；保留异常状态和诊断日志，不发布档位或 R162，等待人工停止/恢复 |

如果 R151 和 R152 在同一轮轮询中同时首次读到 1，先按处理本轮新请求之前的测试状态对 R152 分类。此时测试尚未真正开始，R152 走“未开始测试”分支；R151 仍单独缓存，并在托盘已确认及设备前置条件满足后启动测试。这样不依赖处理函数的先后顺序。

## 验收场景

1. R152=1、测试未开始：日志显示无 NG 档位，PLC 收到 R162=1；DT 无写入。
2. 测试进行中收到 R152=1：只记录暂存；初测/复测结束后先确认 R161，再写最终 NG 数据，最后确认 R162。
3. 测试完成且最终 NG 集合为空：无 DT 写入，R162 仍确认成功。
4. 测试完成且有多个 NG：每个最终 NG 点位只写一次并按顺序确认，所有成功后才写 R162。
5. 同一轮首次采样 R151=1 与 R152=1：R152 按采样前测试状态立即确认；R151 按托盘和设备前置条件独立启动或暂存。
6. DT 写入或 R162 确认超时：流程不提前报告完成；恢复后只重试未确认的阶段。
7. 点击停止：清空软件流程请求并回到等托盘状态；日志不出现对 R150/R151/R152 的写入。
