# 日志管理优化实施计划

> **执行约定：** 仅修改日志管理、其明确的业务日志入口和对应验证文件；保留工作区内其它功能的未提交内容。最终只提交本计划和日志功能相关改动。

**目标：** 修复日志采集和报警兼容的完整性问题，明确事件语义与统计口径，提升导出和故障可见性，并通过针对性回归检查后提交。

**架构：** 保留现有按日追加的结构化文本日志、旧 `AlarmLog.txt` 导入和 WinForms B 方案。统一报警文本解析与去重规则；由日志服务集中执行筛选和 CSV 单元格防护；业务日志故障继续不阻断测试、校准或设置流程，但记录可见的健康状态。

**技术栈：** VB.NET、.NET Framework 4.8、Windows Forms、PowerShell runtime verification。

---

## 优化方案

1. **报警完整性：** 以完整时间戳解析报警行，不按第一个冒号截断；结构化报警和旧文件共用解析结果与摘要规范；把 NG 判定接入结构化报警日志，旧报警文本继续兼容。
2. **操作语义：** 失败登录明确记录尝试账号；手动测试使用“手动测试”事件标识；Runner 只报告测量阶段完成，结果持久化边界再报告保存成功或失败。
3. **查询口径：** 服务和页面共用同一筛选函数；统计卡片显示所选日期范围内的分类数量，避免“今日”与历史区间混读。
4. **导出安全：** 对 CSV 中以公式前缀开头的字段做文本化处理，再执行标准 CSV 引号转义。
5. **故障可观测性：** 记录最近一次业务日志读写错误，查询页面展示状态；业务操作仍不因日志异常抛错中断。
6. **避免过度建设：** 不新增数据库、后台服务、通用审计框架、非日志重构或无依据的保留周期。旧文件扫描优化仅在不改变记录语义且实现足够小的情况下纳入。

## 实施方案

- `BusinessLogService.vb` 负责报警行规范化、历史去重、筛选规则、CSV 安全编码和读写错误状态。
- `frmTest.vb`、`FormalTestRunner.vb`、`FrmManualTest.vb` 只补充报警/测试事件的准确日志边界。
- `FrmLoginNew.vb` 修正失败登录的事件用户；`FrmLogQuery.vb` 与 Designer 调整统计文案并呈现日志状态。
- `tools/Test-BusinessLogServiceRuntime.ps1` 提供隔离的回归检查，覆盖报警解析/去重与 CSV 公式输入；测试数据必须放在临时目录，不读写真实用户日志。
- 混合了其它功能改动的文件只暂存与日志有关的差异；不提交其它工作区改动。
