# 启动设备检查与首屏 UI 解耦设计

## 目标

让 MDI 主页面和 `frmTest` 首屏先完成显示，设备连接、重试、读取和超时处理全部在后台执行；启动失败通过状态栏和日志反馈，不用模态对话框阻塞 UI。同时记录完整启动阶段耗时，定位剩余的 20 秒延迟。

## 设计

1. `ApplyCheckResultsToUi()` 只写入设备状态文本、颜色和连接标志，不调用 `ConnectFor34461()`、`ConnectFor3561()`，不显示 `MessageBox`/`MsgBox`。
2. 新增后台启动设备检查边界，串行执行现有 SCM、34461、3561、PLC、MES 检查及必要连接初始化；异常转换为结果对象，统一由 UI 回调更新状态栏和日志。
3. `frmTest_Load` 只执行首屏必需的容器布局、控件初值和通道网格准备。首次 `Paint` 后通过一次性延后任务执行视觉样式、启动 `timer3`/`Timer4` 和其他轮询。
4. 使用共享 `StartupTiming` 记录主窗体 `Shown`、`frmTest_Load`、必要布局、延后样式、首次 `Paint`、设备检查开始/结束和 UI 回调时间。

## 错误处理

启动期设备错误写入日志并显示在底部状态栏；不从后台线程或 UI 回调弹模态框。每项设备检查沿用现有有限超时，异常结果必须继续汇总其余设备状态。

## 验证标准

- 静态回归脚本确认 UI 回调不含设备重连和模态弹窗。
- 静态回归脚本确认定时器只在首屏绘制后的延后入口启动。
- Release x86 编译通过。
- 启动计时日志能分别显示首屏阶段和设备检查阶段，且设备检查不阻塞首屏 Paint。
