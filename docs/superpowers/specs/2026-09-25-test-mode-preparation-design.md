# 自动与手动测试准备流程统一设计

## 已确认的业务规则

- 自动与主页面手动模式使用同一套正式测量、判定和保存逻辑。主要差异是托盘码来源与启动信号：自动从扫码器取得托盘码，手动由操作员扫入或输入 `txtTray` 后点击“启动测试”。
- 自动每轮测量物理通道 1～256，即使托盘只有部分电芯。没有电芯码的空位保留测量过程，但不写入 OCV_DATA 正式电芯结果，也不进入电芯 NG 复测集合或 MES 电芯上传。
- 手动只测操作员所选物理通道；所选通道必须在本次托盘查询结果中有有效电芯码。
- 自动扫码成功后先校验托盘码、重新加载本次托盘电芯码并清空旧缓存，再发 R160。手动点击启动时执行相同的托盘码及电芯码准备。查询失败、重复通道、非法通道、重复电芯码或无有效电芯码均阻止启动。
- 自动扫码失败进入故障提示，操作员可切换手动模式输入托盘码；自动周期本身不弹出手工输入框。
- 测量前检查登录、报警、中位机和仪表通信、夹具压合状态及通道计划。自动由 R151 低到高确认压合；手动从 PLC 读取夹具状态。设备异常时不创建正式任务、不开始测量。

## 运行与结果

准备阶段生成本轮不可变的托盘码、通道集合及电芯码快照。`StarTest` 使用该快照；自动复测沿用同一托盘周期，不再把相同托盘码当作新托盘重复。测量结果与电芯业务结果分开：自动对 256 个通道测量，数据库、MES 与电芯 NG 判定只处理有电芯码的通道。手动对选中通道测量并保存。

正式保存失败不得发 R161，也不得启动手动 NG 复测。自动最终保存与 R161 分别记录状态；R161 写入或确认失败时保留已保存的任务信息，重试通知不能重新测量或创建任务。PLC 响应按 MEWTOCOL 成功类型及 BCC 校验，而不是任意非空文本。MES 后台上传读取本轮数据快照，不能读取下一托盘覆盖后的全局数组。

PLC 成功响应类型与 BCC 依据 [Panasonic MEWTOCOL-COM 手册](https://ac-blog.panasonic.co.jp/hubfs/PLC/ACG-M0015-2.pdf)。现有 R150/R151 命令帧属于现场协议配置，仍须以实机通信记录核对。

## 模式隔离

自动周期从扫码开始至 PLC 完成通知或故障处理结束，主页面手动启动和模式切换不可抢占设备。手动测试期间不能切到自动。独立的菜单“手动测试”仍是调试功能，不写正式任务，不能与正式测试或自动 PLC 流程并行。

## 验证

以无实机的回归测试覆盖：部分电芯托盘的自动全测与正式结果过滤、手动选通道与缺码拒绝、同托盘自动复测、保存失败不复测不放行、模式互斥、PLC 错误响应拒绝。再执行现有脚本和 x86 Debug 构建。R151 时序、真实 PLC ACK、仪表与夹具行为需要现场联调确认。
