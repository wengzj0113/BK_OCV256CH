# PLC/MES 托盘电池条码获取改造设计

## 背景与目标

现有流程依赖上位机扫码程序、扫码枪串口和 `frmInput` 手动录入/生成条码。目标是改为由 PLC 负责扫码、上位机读取 PLC 中的托盘码，再从客户 MES 数据库加载托盘内电池条码。

本次改造还增加两种运行模式：

- 自动模式：MES 条码加载成功后自动开始 OCV 测试。
- 手动模式：MES 条码加载成功后只更新界面和测试数据，仍由操作员点击“启动测试”。

主页面的模式选择放在左侧栏图片箭头所指的位置，即“托盘与电池”区域内、“待测试通道数”下方和测试按钮上方。

## 设计范围

本次范围包括 PLC 托盘到位/托盘码读取、MES 数据库连接与查询、托盘条码自动加载、自动/手动测试分流、配置保存和旧扫码链路移除。

OCV 测试仪器、OCV 测试结果保存、MES 结果上传和 `OCV_DATA` 业务库的既有职责不改变。客户 MES 数据库只作为电池条码来源，不承担 OCV 测试结果写入。

## 总体架构

采用三个职责清晰的模块，并以 `frmTest` 作为界面协调者：

1. `PlcController`：封装 PLC 连接、托盘到位信号读取和托盘码寄存器读取。
2. `MesDataService`：使用独立连接配置访问客户 MES 数据库，按托盘号查询 `dbo.batcode`。
3. 托盘条码流程模块：负责轮询、去重、状态转换、MES 查询、通道数据校验和向界面发布加载结果。

`frmTest` 只负责显示状态、维护自动/手动模式和调用现有测试入口；不直接拼接 SQL，不解析 PLC 帧，也不再启动扫码程序。

现有代码中的旧自动启动路径必须一并移除：`autoStartFlag`、`AnalyzeData`/`checkJIGSignal` 对旧 IO 自动启动位的解析，以及 `Timer4_Tick` 根据该标志调用 `StarTest(1)` 的行为，都不能继续与新的模式选择并存。自动测试的唯一触发条件是“当前选择为自动模式 + 当前托盘条码成功加载 + 当前没有测试运行”。

MES 数据加载后必须同步更新 `ChannelGridControl` 的物理通道选择。当前窗体启动时默认选中全部通道的行为需要改为初始无选择，加载成功后按 `Tf_ChannelNo` 批量选择实际通道。`frmTest` 不得再通过 `frmInput.txtFirst/txtLast` 推导测试范围，测试范围以 MES 返回的物理通道集合为准。

PLC 地址和编码格式目前尚未最终确定，因此不写入 `frmTest` 或 MES 查询逻辑。地址、寄存器数量、字符串编码和轮询超时作为 PLC 配置项，由取得 PLC 地址表后填入。

## 运行流程

```text
等待托盘
  ↓ PLC 托盘到位信号为真
读取 PLC 托盘码寄存器
  ↓ 托盘码有效
查询 MES_Data.dbo.batcode
  ↓ 返回通道与条码
校验并加载 RecieveData
  ↓
手动模式：等待操作员启动
自动模式：调用 StarTest(1)
```

### 托盘到位与重复处理

- 上位机通过后台轮询读取 PLC 托盘到位信号，不能阻塞主界面。
- 托盘到位信号需要做边沿/稳定时间判断，避免一个托盘被重复处理。
- PLC 接口必须区分“托盘到位”和“夹具闭合/测试允许”；新托盘识别不能替代现有测试前的夹具状态确认。
- 优先使用 PLC 的扫码完成/数据有效信号；如果 PLC 没有该信号，则只有在寄存器值非空、连续读取一致且未超时后才接受托盘码，避免读取上一个托盘的残留值。
- 托盘码成功处理后记录当前托盘码；在托盘离开或信号恢复为未到位前，不重复加载同一托盘。
- 读取托盘码超时、为空或 PLC 通讯异常时，停留在等待/错误状态，不触发自动测试。

流程需要使用单一进行中锁：PLC 轮询、MES 查询和自动启动之间只能有一个托盘处理任务。测试运行期间忽略新的托盘到位事件；测试完成、结果保存结束、托盘离开后才允许开始下一个托盘。

### MES 查询与通道映射

MES 数据库连接参数全部来自 `Initsetting`：

```text
服务器：MesDatabaseServerIP
数据库：MesDatabaseName
用户：MesBaseUser
密码：MesBasePsw
```

查询使用参数化 SQL：

```sql
SELECT Tf_ChannelNo, Tf_CellSn
FROM dbo.batcode
WHERE Tf_TrayId = @TrayCode
```

字段映射固定为：

```text
Tf_TrayId     → 托盘号
Tf_ChannelNo  → 设备物理通道号
Tf_CellSn     → 电池条码
```

每条数据直接写入对应物理通道：

```text
RecieveData(Tf_ChannelNo - 1).BatCode = Tf_CellSn
```

不按查询结果重新编号、不把稀疏通道压缩成连续通道。通道号必须在 1～256 范围内；重复通道、空条码、空托盘结果和非法通道均视为加载失败，并显示明确原因。

按当前 256 通道设备的生产约束，MES 返回记录数少于 256 时视为托盘数据不完整，自动模式禁止启动；手动模式也禁止直接启动，必须显示缺失通道，待数据完整后重新加载。查询结果必须满足 `(Tf_TrayId, Tf_ChannelNo)` 唯一。

MES 若因生产系统同步延迟暂时没有记录，允许在单次托盘处理任务内按配置次数重试；重试仍无有效结果则失败。托盘号按字符串原值去除首尾空白后查询，不做数值转换或补零。

### 自动与手动模式

左侧增加“测试模式”区域，包含两个互斥单选框：

```text
○ 自动模式
○ 手动模式
```

建议默认手动模式。模式切换在测试运行期间禁用，避免测试中途改变行为。

- 自动模式只有在 PLC 托盘码有效、MES 查询成功、通道数据校验通过后才调用 `StarTest(1)`。
- 手动模式完成相同的数据加载和界面刷新，但不调用 `StarTest(1)`。
- 自动启动必须使用现有测试入口，继续执行原有报警、OCV 选择、夹具、测试任务、保存和上传流程。
- 自动模式不得弹出需要操作员确认的 OCV 次数对话框；使用当前已选定的 OCV 工位/阶段。NG 复测仍保留人工确认，不在自动模式下无限递归复测。
- 自动模式启动失败时只记录一次失败并回到错误/待处理状态，不能因为后台轮询再次重复启动。
- 手动模式下，MES 返回的有效通道默认全部选中；操作员可以在测试开始前调整通道选择，但启动前必须再次校验所有选中通道均有电池条码。自动模式加载完成后锁定通道选择，直到本次测试结束。

## 配置设计

### MES 配置控件

在 `frmInit` 的数据库设置页增加并使用以下控件：

```text
txtMesDatabaseServerIP  MES 数据库服务器 IP
TxtMesDatabaseName      MES 数据库名称
TxtMesBaseUser          MES 数据库登录名
TxtMesBasePsw           MES 数据库密码
```

密码控件启用密码掩码。保存配置时不在源码中写入服务器、数据库名称、用户名或密码；配置为空时，在读取 MES 前提示用户配置完整信息。

建议在同一设置页增加“测试 MES 数据库连接”按钮，连接测试必须复用正式 `MesDataService` 的连接字符串和超时设置。连接测试不得读取或修改 OCV_DATA 配置，也不得执行写入操作。

### 与 OCV_DATA 的隔离

现有 `strDatabase`、`strUserID` 和 `strpwd` 继续只服务于 `OCV_DATA`。MES 连接不得读取或覆盖这三个字段，也不得让 `OcvDataService` 负责 MES 条码查询。

`MesDataService` 使用独立的连接字符串构造逻辑。数据库名称也必须使用 `Initsetting.MesDatabaseName`，不在代码中固定为某个数据库名。

### 配置文件兼容

`Initset` 增加四个 MES 配置字段，`SaveInitFile()` 将其追加保存，`ReadInitFile()` 在文件末尾存在数据时读取，否则使用空字符串。这样旧版 `Initset.set` 仍可读取，但在用户填写 MES 配置前不能执行 MES 条码加载。自动/手动模式不写入配置文件，程序每次启动默认手动模式，避免设备重启后意外自动启动。

## 旧扫码链路处理

删除或从项目入口移除以下逻辑：

- `frmInput` 中的扫码窗口、`CWtray.exe` 启动和共享内存 `MpScanGui_ReturnInfo`。
- `ThreadSaveCode`、`MapReadBarCode`、`ScanBarCode`、`CommunicationScan` 等扫码采集逻辑。
- 首尾条码自动递增生成逻辑。
- 主页面和 MDI 菜单中的旧扫码按钮/入口。
- 扫码枪端口和波特率配置，以及仅服务旧扫码链路的串口初始化代码。
- `autoStartFlag` 及其旧 IO 自动启动链路，包括 `Timer4_Tick` 中直接调用 `StarTest(1)` 的逻辑。

删除前必须确认被称为 `Com_scaner` 的串口没有被测试仪器流程复用；只删除扫码职责，不能误删 3562A、34461A、中位机或 PLC 的通讯。

原先 `frmInput` 中的本地 OCV 托盘明细查询不能继续作为 MES 查询实现。查询职责迁移到 `MesDataService`，`SaveCurrentTrayCellsToOcvData()` 也不再把客户 MES 数据回写成 OCV_DATA 托盘明细，除非后续另有明确业务要求。

删除 `frmInput` 前必须先移除 `frmTest`、`MDIForm` 和项目文件中的所有引用，包括旧的 `txtFirst/txtLast` 数据传递。`bar.set` 条码缓存也随旧扫码链路一并停用，不作为 MES 不可用时的离线兜底。

## 错误与安全边界

以下情况禁止开始自动或手动 OCV 测试，并在左侧状态区域或报警区域显示原因：

- PLC 未连接或托盘未到位。
- 托盘码寄存器读取失败、为空或解码失败。
- MES 配置不完整、连接失败或 SQL 查询失败。
- `batcode` 没有该托盘记录。
- `batcode` 返回少于 256 个有效通道，或存在缺失通道。
- 通道号超出 1～256、重复或条码为空。
- 条码加载未完成或当前托盘数据不完整。

SQL 必须使用参数 `@TrayCode`，不得拼接用户输入。MES 查询只读，不执行插入、更新或删除。

PLC 和 MES 的后台任务不能直接操作 WinForms 控件，所有状态、提示和通道选择更新必须切回 UI 线程。错误提示需要带阶段信息（PLC 到位、PLC 托盘码、MES 连接、MES 查询、数据校验或自动启动），日志中不得记录 MES 密码。

## 测试验收标准

### 单元/模块测试

- 使用模拟 PLC 验证托盘到位边沿、托盘码解码、超时、空码和重复码抑制。
- 使用测试连接字符串验证 MES 查询只访问 `batcode`，字段映射正确，托盘码通过参数传递。
- 验证 1、256、稀疏通道、重复通道、非法通道和空条码数据。
- 验证少于 256 条记录时自动模式和手动模式都不能启动，并显示具体缺失通道。
- 验证 OCV_DATA 连接配置与 MES 连接配置互不影响。
- 验证 MES 查询超时/暂时无数据时的重试和最终失败行为。

### 界面与流程测试

- 确认模式选择控件位于左侧箭头所指区域，自动/手动互斥且测试中不可切换。
- 手动模式加载成功后不自动启动测试，点击启动后仍能正常测试。
- 自动模式加载成功后只启动一次 OCV 测试。
- 确认旧 `autoStartFlag` 和 `Timer4` 不会在手动模式下触发测试，自动模式不会被旧 IO 信号重复触发。
- 确认 MES 通道集合会同步到通道选择控件，空条码通道不可被启动测试选中。
- PLC、MES 或数据校验失败时不启动测试，并可在恢复后重新处理新托盘。
- 旧扫码按钮、扫码窗口和 `CWtray.exe` 不再被调用。

### 现场联调前置条件

现场联调前必须取得 PLC 地址表，至少包含托盘到位信号、夹具闭合/测试允许信号、托盘码寄存器起始地址/数量、编码方式、扫码完成/数据有效状态以及托盘离开状态定义。未取得这些协议参数时，只能完成模拟 PLC 和 MES 的软件验证，不能宣称现场自动采集流程完成。
