# 调试中心窗口重设计方案

## 目标

将现有 `frmDebug` 从临时按钮集合改造成一个可用于现场排障的调试中心：先看所有设备和接口状态，再进入通信收发、手动控制或日志；保留现有测试流程和协议实现，避免调试操作误启动正式测试。

## 现状依据

- 现有 `frmDebug` 将单片机、内阻仪、Socket、34461A、通道测试和托盘操作混在两个页签中，包含 `Button1`、`sockTest`、`TestComm16` 等不可解释名称。
- 项目已有可复用的设备入口：`CheckCom_SCM`、`ConnectFor3561`、`CheckCom_34461`、`IPlcController`、`SerialMiddleMachineClient`。
- `SerialMiddleMachineClient` 是当前中位机/RS485 的协议层；本次不复制其协议逻辑。
- 当前仓库是 .NET Framework 4.8 的 VB WinForms 非 SDK 项目，新增源文件必须登记到 `.vbproj`。

## 用户任务与信息架构

窗口固定为四个功能区：

1. **设备总览**：设备卡显示名称、接口、配置、状态、最近测试时间、最近结果和“测试连接”；顶部显示已连接/待检查/失败数量，并提供“一键检查全部”。
2. **通信控制台**：选择支持的接口，输入十六进制或 ASCII 报文，发送并查看带时间戳的收发记录；发送前检查正式测试是否运行，危险操作不默认提供“启动测试”。
3. **手动控制**：中位机安全复位、读取基础状态、下发单通道选择（不启动测试）、PLC 托盘状态/开/关/复位；打开/关闭托盘和下发通道计划必须二次确认。
4. **运行日志**：按时间显示调试动作、设备结果、错误和耗时；支持复制、清空当前视图和导出文本。

设备清单纳入：

- SCM 控制板 / 单片机（当前控制板串口协议检查）
- 中位机 RS485（与 SCM 共用当前 `Com_SCM` 的协议层）
- 日置 3562 内阻仪
- Keysight 34461A 数字万用表
- PLC / 托盘夹具
- IO 卡 / 扫码器（显示真实串口状态；IO 卡注明由控制板管理）
- 数据库 / MES 作为应用通信状态卡，若当前项目没有安全的探测入口则只显示配置与上次状态，不伪造在线结果

## 组件边界

### `DebugModels.vb`

只定义 `DebugDeviceId`、`DebugDeviceResult`、`DebugLogEntry` 和事件参数，供窗体、UI 控件和探测服务共享。结果统一包含状态、消息、耗时和时间。

### `DebugProbeService.vb`

只负责调用现有通信入口并返回结果：SCM 使用 `CheckCom_SCM(True)`；3562 使用 `ConnectFor3561(True)`；34461A 使用 `CheckCom_34461()`；PLC 使用当前 `plcController` 或 `PlcControllerFactory` 连接并读取托盘状态；串口设备读取 `IsOpen`；数据库/MES 不做未经确认的外部写入。服务捕获异常并返回失败结果，不弹窗、不直接更新控件。

### `DebugDashboardControl.vb`

只负责界面和用户交互，采用 WinForms 标准控件动态构建，使用 `UiTheme` 统一颜色/字体。通过事件把“测试某设备、检查全部、发送报文、手动控制、清空日志、关闭窗口”等动作交给宿主窗体，不直接访问全局通信对象。

### `frmDebug.vb`

保留原有事件入口和公共 `mSock`/`mSocket` 兼容性。加载时完成权限校验后隐藏旧控件、挂载 `DebugDashboardControl`，实现事件到现有业务/通信入口的适配。正式测试运行时禁止会影响共享串口或 PLC 状态的手动动作。

## 关键交互和安全规则

- 窗口打开后不自动向设备发送命令，只显示“待检查”；用户可单卡检查或一键检查。
- 一键检查按设备顺序串行执行，避免多个线程同时争用 COM/VISA/PLC 资源；每项完成立即刷新对应卡片。
- 设备检查不使用 MessageBox；结果在卡片和日志中可见。
- 原始发送仅允许支持的串口接口；SCM/RS485/3562 发送前确认端口已打开。VISA/PLC 使用专用检查或操作入口，避免把未暴露的会话对象强行包装成假通道。
- `isRuning=True` 或应用正在退出时，禁止探测和手动控制，并在日志说明原因。
- 托盘开/关、通道计划下发、复位等动作分别显示确认文本；复位提供“恢复安全状态”含义，不启动正式测试。
- 所有后台操作完成后通过 `BeginInvoke` 回到 UI 线程，窗体关闭时取消/忽略未完成的 UI 更新。

## 验收标准

- 窗口首次打开显示四个清晰功能页和设备状态列表，不再展示旧的英文临时按钮。
- 单卡检查、一键检查和结果日志能够工作；失败显示明确的接口/配置/异常信息。
- 通信控制台能够对已打开的串口执行十六进制/ASCII 收发并展示原始数据。
- 手动控制包含中位机安全操作和 PLC 托盘操作，正式测试运行时有阻断。
- 现有旧按钮事件和正式测试相关引用仍可编译，未改动核心测试、数据库和 MES 流程。
- 通过源代码契约检查、WinForms Designer 序列化检查，并在可用环境下完成 .NET Framework 构建；若当前环境缺少完整 MSBuild/厂商依赖，明确记录环境阻断，不把它误报为代码通过。
