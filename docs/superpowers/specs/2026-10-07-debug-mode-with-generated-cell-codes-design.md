# 无电芯码调试模式设计

## 目标

测试阶段尚未取得真实电芯码时，操作人员仍可运行设备测试流程，并将带有调试标记的结果写入 OCV_DATA 供当前结果查询和历史排查。调试条码不能被误当作生产电芯码，调试结果不能上传到生产 MES，也不能覆盖或隐藏正式测试结果。

## 现状与约束

- `frmTest.Designer.vb` 已有主页面复选框 `chk_Test`，文字为“调试模式”；勾选状态作为调试模式开关。本次不增加新的复选框。
- 测试任务仍需要有效托盘码。调试模式只替代电芯码，不替代现有托盘码校验和 PLC 托盘握手。
- 正式测试通过 `PrepareTrayForTest` 按托盘码查询 MES/OCV_DATA 电芯码，并由 `TrayTestPreparation` 校验通道和条码。
- 手动测试完成后创建 OCV_DATA 任务、保存结果和本地文件，并可启动 MES 上传。PLC 自动测试在初测/复测结束后统一保存最终结果，也可启动 MES 上传。
- `TestTask.TestType` 已可区分任务类别，`TestResult.ResultSource` 已可区分结果来源；不新增调试标记字段。
- `usp_GetTrayLatestStageResults` 当前会按托盘和阶段选最新任务，必须区分调试与生产结果，避免调试结果影响生产查询。
- 自动流程当前只为一个托盘周期的最终结果创建 OCV_DATA 任务；本设计保留该策略，不为内部初测和 NG 复测轮次另建任务。

## 交互与模式生命周期

1. `chk_Test.Checked = True` 表示调试模式；程序启动时默认未勾选，模式不持久化。
2. 仅在手动测试空闲且 PLC 自动托盘周期空闲时允许切换。测试启动后锁定复选框，直到本次手动测试或整个自动托盘周期结束。
3. 调试模式仍要求有效托盘码。生成条码不调用 MES 电芯码查询，也不改变 PLC 托盘码读取、校验、启动、复测、完成和复位握手。
4. 用户取消调试模式时，清除内存中的调试条码和调试测试计划；正式测试启动前必须重新加载真实电芯码，不得沿用调试计划。
5. 复选框勾选状态应与调试模式状态保持一致；不增加新的模式控件，也不改变现有页面布局。

## 条码和测试计划

- 条码格式为 `TEST-yyyyMMdd-通道号`，日期使用设备本地日期，通道号使用 1～256 的十进制通道号，例如 `TEST-20261007-1`。
- 手动模式为本次实际选择的通道生成条码；PLC 自动模式为现有自动测试计划中的全部测量通道生成条码。条码在一次完整测试运行开始时生成并固定，自动流程的初测和 NG 复测使用同一组条码。
- 条码是调试占位标识，不表示真实电芯身份，也不注册到 `TrayCell`。相同日期和通道会有意复用同一条码；数据库任务主键及实际托盘码仍用于区分每次运行和历史记录。
- 调试计划仍通过现有测试入口执行设备检查、测量、规格判定、本地结果保存、OCV_DATA 结果保存和任务状态完成。生产模式的严格条码完整性校验保持不变。

## OCV_DATA 记录与查询

- 调试任务使用 `TestTask.TestType = 'Debug'`，调试测量结果使用 `TestResult.ResultSource = 'Debug'`。任务代码和幂等键应包含调试类型，并继续按每次独立运行生成唯一值。
- 每次手动调试运行和每个 PLC 自动托盘周期均保留独立任务及其结果。重复条码不更新或删除旧任务；历史任务用于排查，当前调试结果查询按实际托盘、测试阶段和通道返回最新一次已完成的调试任务结果。
- 生产结果查询只选生产任务，不允许调试任务成为托盘阶段的最新生产结果。调试结果查询只选调试任务。
- `frmInquery` 提供默认未勾选的“调试结果”筛选；按日期加载托盘列表和按托盘查询结果都使用同一筛选状态，切换时刷新列表和当前结果。
- NG 复测来源查询不得返回调试结果作为生产复测来源。调试模式自身的自动 NG 复测继续使用当前自动流程内存结果，不改变其 PLC 周期行为。
- 结果同时保留真实托盘码、测试阶段、物理通道、测试任务号和生成的调试条码，保证既可按托盘/阶段查询，也可审计单次运行。

## MES 和 PLC 边界

- 调试模式禁止在手动测试完成分支启动生产 MES 上传，也禁止 PLC 自动周期最终完成分支启动生产 MES 上传；不将调试任务写入生产 MES 上传队列。
- 若测试启动时已由另一项正式任务启动 MES 后台上传，本设计不取消那项既有任务；调试模式只禁止当前调试结果触发新的生产上传。
- PLC 自动模式允许使用调试模式，托盘码采集和现有 PLC 握手保持不变。调试标志必须贯穿初测、自动 NG 复测、最终保存和流程完成，不能在最终保存时退回正式类型。

## 失败处理

- 无法读取有效托盘码时，调试模式和正式模式一样禁止启动。
- 通道计划无效、调试条码生成失败或数据库任务创建失败时，测试不得继续；显示具体原因，并按现有手动/自动失败路径记录状态。
- OCV_DATA 保存失败时，任务按现有规则标记失败；不触发 MES 上传。
- 调试模式中途被取消或测试失败时，保留已创建任务及状态用于排查；切回正式模式后仍要求重新加载真实条码。

## 验收标准

- 未勾选 `chk_Test` 时，测试行为与现有正式流程相同：按托盘码加载真实电芯码、执行严格校验、保存正式任务和结果，并按现有设置触发 MES 上传。
- 勾选时，手动和 PLC 自动模式均可在没有 MES 电芯码的情况下生成正确格式的条码并完成测量；自动周期保留原有 PLC 握手及 NG 复测行为。
- 每次调试运行在 OCV_DATA 中有独立任务记录，任务类型为 `Debug`，结果来源为 `Debug`；相同条码重复测试后，历史记录仍存在，当前查询返回最新结果。
- 托盘最新结果查询和生产 NG 复测查询不会把调试结果当作生产结果；调试结果查询可以显示当前托盘、阶段和通道的最新调试结果。
- 调试手动流程和调试 PLC 自动流程均不启动生产 MES 上传；其他正式流程的 MES 上传行为不变。
- 测试中不能切换模式；取消调试模式后，正式测试不会使用遗留的 `TEST-` 条码或调试计划。
