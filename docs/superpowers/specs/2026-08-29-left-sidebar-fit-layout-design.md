# frmTest 左侧栏全控件布局设计

## 目标

在不改变测试、通讯、数据库和 MES 业务行为的前提下，重做 `frmTest` 左侧栏的显示布局，解决以下问题：

1. 左侧栏内部分控件因固定坐标、父容器尺寸或布局重排顺序不当而被裁剪。
2. 左侧栏底部出现与实际内容无关的空白。
3. 工作站显示不符合新的操作要求：工作站位于左栏最顶部，只显示 `frmInit` 设定的当前工作站，按钮尺寸约为现有按钮的 2 倍。

## 现状与根因

- `Panel1` 承载多个历史 `GroupBox`，部分子控件仍依赖 Designer 中的固定 `Location/Size`。
- `ResponsiveTestLayout` 已经引入 `LeftControlContent`，但如果父子容器同时使用固定高度、自动尺寸和滚动，可能出现内容高度计算滞后或最后一项被裁剪。
- 工作站控件原本位于 `GroupBox2` 中，多个 OCV 选项与容器标题占用左栏高度；新需求只需要显示一个已设定的工作站。
- 左栏内容不足可视高度时，不能通过人为增加内容高度或空白占位来“填满”面板；左栏应该填满窗口，内容高度应由最后一个真实控件的底边决定。

## 设计方案

### 1. 左栏外层与滚动边界

- 根布局的左栏继续使用 `Dock = Fill`，高度始终跟随窗口可视区域。
- 左栏只保留一个负责滚动的 `Panel1`，避免内外层重复滚动。
- `LeftControlContent` 使用顶部对齐，并按真实子控件高度累加内容高度。
- 不使用空白 `Spacer`、固定的超大 `AutoScrollMinSize` 或比真实内容更高的内容面板来填充底部。
- 当内容高度不超过左栏客户区时，左栏不显示纵向滚动条；当窗口缩小导致内容超出时，滚动整个左栏内容面板，任何单个控件都不得被父容器裁剪。
- 普通 Resize 只重新计算宽度和内容高度，不强制把用户已经滚动的位置复位；启动完成后的首次布局可以显式复位到顶部。

### 2. 左栏控件顺序

左栏由上到下排列如下：

1. 当前工作站单个按钮。
2. 测试控制：自动、手动。
3. 控制板：托盘码、待测试通道数、启动测试、停止测试、NG 点测试、托盘状态、开启托盘、闭合托盘。
4. 通道选择：全选、清除、框选、单选。
5. 合格范围设置：电压和内阻的 Min/Max。
6. 报警指示：温度 1~4、烟感 1~2、设备状态。
7. 探针使用次数统计。
8. 事件日志。
9. 报警复位。

每个业务区块使用自然内容高度，区块之间使用统一的小间距。最后一项报警复位之后立即结束内容面板，不再追加无业务意义的空白。

### 3. 工作站显示

- 删除原“工作站选择”视觉容器及其多工位选项展示。
- 根据 `Initsetting.stationSelect` 映射当前工作站：`0 → OCV0`、`1 → OCV1`、`2 → OCV2`。
- 运行时只保留一个可见的当前工作站按钮，放在左栏第一个位置；其他工作站控件隐藏或不加入当前显示布局。
- 当前工作站按钮使用独立的布局项，不再依赖 `GroupBox2` 的固定坐标。
- 按钮宽度随左栏内容宽度伸缩，高度和字号约为原工作站按钮的 2 倍；按钮放大后占用的高度必须计入内容总高度。
- 当前页只展示工作站，不在测试页提供运行中切换工作站的入口，避免测试阶段和数据字段发生不一致。

### 4. 区块内部对齐

- 使用 `TableLayoutPanel` 或 `FlowLayoutPanel` 管理需要对齐的控件，不再以 Designer 的绝对坐标作为运行时布局依据。
- 控制板按钮按可用宽度分成两行，确保启动/停止/NG 点测和托盘操作按钮都完整可见。
- 通道选择四个按钮保持同一行；若低于最小宽度，则整个左栏进入滚动或缩放策略，不允许按钮互相覆盖。
- 合格范围的 Min/Max 表头分别居中于输入框列，电压和内阻输入列上下对齐。
- 报警温度和烟感使用两列网格，设备状态位于底部；不得因为隐藏状态控件而留下异常大间隙。
- 事件日志使用明确的固定高度范围，避免日志控件把后续报警复位按钮推到可视区之外。

## 代码边界

允许修改：

- `ResponsiveTestLayout.vb`：左栏外层、内容高度、滚动边界、区块顺序和内部布局。
- `frmTest.vb`：当前工作站映射、工作站控件显示、启动布局调用和必要的尺寸配置。
- `frmTest.Designer.vb`：仅在需要解除历史固定坐标或补充控件声明时修改。
- `UiTheme.vb`：统一工作站按钮尺寸、左栏间距和相关视觉样式。
- 左栏相关的静态检查和运行时验证脚本。

禁止修改：

- `btnStart`、`btnStop`、`btnNGTest`、托盘操作、通道选择等事件的业务语义和绑定。
- PLC、中位机、34461A、3562A、数据库、MES 和测试数据流程。
- `stationSelect` 的业务含义和已有 `OCV0/OCV1/OCV2` 映射规则。

## 验收标准

### 可见性与边界

- 在基准生产窗口中，左栏的工作站、测试控制、控制板、通道选择、合格范围、报警、探针统计、事件日志和报警复位全部可见。
- 任一可见控件的 `Right` 不得超过父容器客户区宽度，`Bottom` 不得超过其父容器客户区高度。
- 左栏内容末尾与报警复位按钮的实际底边一致，不存在人为追加的底部空白。
- 窗口缩小时，左栏可以整体纵向滚动，滚动后可以访问所有控件；不得出现单个控件被截断或横向滚动条。

### 工作站

- `stationSelect = 0/1/2` 时分别只显示 OCV0/OCV1/OCV2。
- 当前工作站按钮位于左栏最顶部，尺寸约为原按钮的 2 倍。
- 原工作站选择容器标题和非当前工位按钮不再显示。

### 对齐与回归

- 通道选择四按钮同一行且无重叠。
- Min/Max 表头、输入框列和报警区内部控件对齐。
- 自动/手动模式仍保持互斥，默认自动模式。
- 启动、停止、NG 点测、托盘操作和通道选择行为保持原有结果。
- Debug x86 编译成功，左栏静态检查、运行时布局检查和既有 UI 回归检查通过。
