# 3562 缓存数据解析兼容性设计

## 背景

主页面离散框选测试时，3562 返回的缓存记录可能包含仪表填充格式，例如 `-   0.04E+0`。当前解析器只做首尾空白裁剪，负号和数值之间的填充空格会使 `Double.TryParse` 失败，导致有效记录被跳过，最终上位机报告 `3562 cached data read failed`。

手动测试 256 个连续通道可以成功，因此本次修复不改变通道计划模式、不把离散选择扩展成连续范围，也不改变 PLC 生命周期职责。

## 方案

1. 在 `Trans_ReadCachedData_3562` 的记录解析边界兼容 3562 的数值填充格式：
   - 保留记录分隔和三字段结构：记录号、内阻、电压；
   - 对数值字段清除符号与数字之间的 ASCII 空格；
   - 使用不受系统区域设置影响的 InvariantCulture 解析科学计数法；
   - 保留真实记录顺序，不用记录号重排结果。
2. 保持严格数量校验：解析记录数必须等于测试计划期望数量；不足时失败，避免产生错位结果。
3. 增强日志：记录期望数量、解析成功数量以及空缓存/格式异常原因，便于区分仪表未返回数据和上位机解析失败。
4. 不修改 `SerialMiddleMachineClient` 的同步/独立计划配置，不把 SCM 状态寄存器中的附加状态字段当作缓存数量使用。

## 回归验证

- 回放当前失败日志中的 `-   0.04E+0` 记录，验证可以解析；
- 构造 256 条含正负科学计数法的缓存文本，验证返回 256 条；
- `END` 且无记录时验证明确失败；
- 运行现有主页面通道选择、Designer 序列化、运行时和 x86 Debug 重建检查。
