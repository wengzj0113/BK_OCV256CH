# 快速启动与首屏优先设计

## 目标

本次优化只把“主页面快速显示并可操作”作为启动成功条件。设备连接、数据库查询、Socket 轮询和非必要样式不得阻塞主窗体首次显示。

目标指标：主窗体约 2 秒内出现，测试页首屏约 3 秒内完成绘制并可操作；设备状态在首屏之后异步更新。

## 范围

- 主窗体和 `frmTest` 首屏初始化。
- 启动阶段设备检查的调度和结果回调。
- `GetCN()`、数据库健康检查、`timer3`、`Timer4` 的启动时机。
- 首屏布局的批量化和重复布局抑制。
- 保留现有设备检查功能和底部状态栏反馈。

不改变测试协议、通道业务逻辑、设备通信协议和测试过程中的设备初始化规则。

## 设计

### 首屏启动流程

```text
Application.Run
  -> MDIForm 显示
  -> MDIForm.Shown 调度 frmTest
  -> frmTest_Load 只做首屏必要初始化
  -> frmTest 首次 Paint 完成
  -> BeginInvoke 调度后台启动服务
```

`frmTest_Load` 不启动设备连接、数据库查询、Socket 轮询或完整延后样式。首屏布局使用 `SuspendLayout`/`ResumeLayout(False)` 批量完成，最后只进行一次必要布局。

### 后台启动服务

首次 Paint 后启动一次后台服务，设备检查彼此独立并拥有各自的超时和取消边界。服务完成后只通过 UI 调度更新状态文字和颜色。

UI 回调禁止执行设备连接、设备重试、仪表复位和任何启动弹窗。失败信息只写入状态栏/调试日志；手动重试复用同一后台服务入口。

### 设备检查策略

- 34461 启动检查只做连接和身份确认，不在首屏阶段执行复位。
- 3561、控制板、PLC、MES 检查均在后台执行。
- 单设备启动检查超时不超过 3 秒，避免串行累加造成首屏等待。
- 后台设备服务与测试执行共享设备对象时，必须保持单一操作顺序，禁止检查线程和测试线程同时操作同一串口/VISA 会话。

### 延后工作

首次 Paint 之后再启动：

- `timer3` 和 `Timer4`；
- `GetCN()`；
- 数据库健康检查；
- 完整控件视觉样式；
- 设备轮询和失败重试。

### 布局约束

继续使用 `Dock = Fill` 管理 MDI 客户区和测试页主体。移除首次显示后的重复最大化请求和不必要的手工客户区尺寸同步。`ResponsiveTestLayout` 只在首次构建及实际尺寸变化时布局，避免每个控件属性修改都触发 `PerformLayout()`。

## 错误处理

- 启动阶段不显示模态消息框。
- 后台服务捕获设备、数据库和网络异常，转换为状态结果。
- 窗体关闭时取消尚未完成的后台启动任务，避免回调访问已释放控件。
- 设备未连接不阻止主页面显示；开始测试时继续执行必要的前置连接校验。

## 验证

1. 静态检查：首屏路径不包含设备连接、弹窗和同步数据库调用。
2. 构建 Debug 配置成功。
3. 无设备/网络不可达时，主页面仍在目标时间内显示并保持响应。
4. 设备正常时，首屏先显示，随后状态栏变为已连接。
5. 设备失败时，首屏不弹窗，状态栏显示失败，手动重试可用。
6. 首次显示和取消最大化/恢复最大化后，底部状态栏及测试页内容不被遮挡。
7. 启动计时记录主窗体显示、`frmTest_Load`、首屏布局、首次 Paint、后台服务开始和各设备完成时间。
