# 初始化设置热应用设计 V2.0

## 目标

保存初始化设置后，让当前进程安全应用可运行时重载的参数。普通设置不再默认要求用户退出整个程序；只有无法安全重建的运行状态才要求重启。

## 现状与约束

- `frmInit` 保存时更新 `Initsetting` 并写入 `Initset.set`；当前选择退出才结束主程序。
- 通道颜色已有刷新打开测试页的能力。
- `StartupDeviceService.DeviceStartupCheck` 已统一检查并初始化 SCM、34461A、主 3562、复测 3562、PLC 和 MES。
- `frmTest` 持有 PLC 自动流程、扫码器和 NTC 温度模块等运行时对象；温度模块按需连接，PLC/扫码器在自动测试模式启动时创建。
- 测试过程读取共享的 `Initsetting`，所以不能在正在执行的测试中途替换配置。
- 当前工作区包含其他未提交改动；本次仅对相关代码增量编辑，不回滚或提交这些改动。

## 参数策略

1. 颜色：保存后立即刷新所有已打开测试窗体。
2. 测试规则参数（电压/内阻限值、条码长度、超温阈值、切换延时等）：保存到本机后排队，在当前测试或 PLC 自动托盘周期结束时切换运行配置，避免本轮混用参数。
3. 设备连接参数（SCM、主/复测 3562、34461A、PLC、扫码器、温度模块）：配置保存后停止/释放相关运行时客户端，按新值重新初始化设备，并报告逐设备检查结果。
4. 数据库/MES 参数：数据库连接为按操作创建，保存后异步执行数据库健康检查；MES 地址由设备启动检查重试。
5. 工位选择：空闲时刷新当前测试页的工位控件及自动测试配置；不能安全刷新时提示退出重启。
6. SCM 五项时间参数：保留独立“应用”按钮，直接写设备并在成功时持久化；写入失败时不报告成功。
7. 工程师工艺参数：同样走保存/应用协调器；测试忙时排队到安全边界，不再单独询问是否退出。

### 直接应用与等待安全时机

- **保存后直接应用：** 通道颜色和只影响显示的参数。设置页中的旧式密码字段随配置保存，但当前登录使用独立的 `UserAccountStore`，修改这些字段不会更改账户或当前会话。
- **等待安全边界后应用：** 电压/内阻限值、条码长度、超温阈值、测试延时、探针寿命/计数、工位切换、仪表量程/采样/功能、设备端口/波特率/IP、数据库/MES 连接参数。正在运行的测试继续使用旧快照，当前测试或托盘周期结束后切换新配置。
- **应用动作：** 释放并重建受影响的 PLC/扫码/温度客户端；按变化范围重检 SCM、DMM、主测/复测 3562、PLC、MES；复测仪重检失败需在界面报告；数据库参数变化时执行健康检查；刷新当前测试页与工位控件。
- **必须重启的条件：** 只有相关设备对象或页面无法释放/重建、应用过程报错，或重建后连接检查失败且程序没有可恢复接口时，才提示重启。重启作为故障兜底，不作为普通保存流程。

## 交互与状态

- “保存”按钮先校验并比较新旧配置。
- 有测试、自动测试托盘周期或设备检查正在运行时，先持久化新配置但保留当前运行快照；测试窗体在周期结束后自动提交应用。PLC 自动流程通过周期边界暂停请求阻止它在提交前启动下一托盘。
- 空闲时先持久化配置，再在当前进程启动设备重检查及窗体刷新。
- 设置保存成功和设备应用成功分别反馈。设备应用失败时，配置仍保存在本机，但 UI 显示具体设备失败原因并保留可重试路径。
- 不再默认弹出通用“重启程序使设置生效”确认框；只有当前页面确实无法安全重建时才提示重启。

## 组件边界

- `InitSettingsApplyPolicy.vb`：纯函数式比较两个 `Initset`，输出变化类别及是否需要设备重检、测试规则刷新、页面刷新。
- `frmInit.vb`：保存前安全门、保存配置、调用主窗体应用流程；保留颜色与 SCM 专用即时应用。
- `MDIForm.vb`：协调已有测试窗体刷新、后台设备重检和数据库重检，统一回报检查结果。
- `frmTest.vb`：暴露空闲状态判断和配置重载入口；释放温度/PLC/扫码客户端，刷新测试规则控件、工位控件和颜色，并按旧模式重建 PLC/扫码客户端。
- `StartupDeviceService.vb`：支持调用方知道设备检查是否成功启动，避免并发检查时误报已应用。
- `tools/Test-InitSettingsApplyPolicy.ps1` 与 `tools/Test-InitSettingsHotApplyRuntime.ps1`：验证分类策略和保存/应用入口的关键行为。

## 失败处理

- 保存文件异常：不开始设备重检，不记录应用成功。
- 测试忙：新配置持久化并排队，运行中 `Initsetting` 保持旧值；不会在当前测试中途切换。
- 单设备重检失败：其他检查继续；显示失败设备/原因；配置文件保留新参数，以便修正或重试。
- 后台设备检查已运行：本次应用不能宣称完成；显示“配置已保存，设备检查正在进行/稍后重试”，避免静默跳过。

## 验证标准

- 分类器把颜色、规则、通信、仪表、数据库/MES、工位变化分到预期类别；无变化返回空类别。
- 忙碌时保存路径不写入配置或修改 `Initsetting`。
- 空闲保存路径不触发整个应用退出，调用运行时应用协调器并保存配置。
- 测试窗体重载清理旧客户端，应用新连接/业务/工位/颜色设置；自动 PLC/扫码流程按原模式重建。
- 全项目编译通过，相关运行时脚本通过。
