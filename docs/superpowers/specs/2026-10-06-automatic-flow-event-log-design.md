# 自动流程事件日志设计

## 目标

让操作人员在主界面“事件日志”框中直接看到自动运行当前走到哪一步，便于站在设备旁观察流程进度。

## 设计

- 仅自动流程的关键节点写入主界面事件日志，并带上发生时间。
- 记录自动流程启动、托盘到位并开始扫码、扫码成功（包含托盘码）或失败、托盘码确认、针床到位并开始初测、初测与每轮 NG 复测结果、最终结果保存、本托盘流程完成、设备复位，以及自动流程异常。
- 继续使用现有“事件日志”文本框，不调整界面布局。自动流程日志应从 PLC 自动流程协调器的流程节点显式发出；更新状态栏不应自动变成日志。
- 文本框仅用于自动流程进度；报警、数据库及设备通信记录继续走其现有报警提示或持久化日志渠道，不写入此文本框。
- 轮询等待状态和 PLC 信号重试细节不追加；仅发生流程节点切换时记录一次。流程异常记录一次并说明失败原因。
- 日志追加应适配自动协调器的后台线程，通过现有 UI 调度方式安全更新文本框，并滚动显示最新内容。

## 验收标准

- 一轮自动流程中，用户可从事件日志辨认托盘触发、扫码结果、针床到位、测试进度及最终结果/异常。
- 扫码成功记录托盘码；扫码失败有明确流程记录。
- 等待 PLC 信号期间不会每秒重复写入相同内容。
- 非自动流程日志仍只出现在现有渠道，不混入此文本框。
