# OCV 上位机 UI V2.0 设计说明

## 目标

在不改变现有 OCV 测试功能、256 通道逻辑、数据库、设备通讯和测试流程的前提下，重构 `frmTest` 首页的布局、控件样式和信息层级，使其适合工业现场使用，并降低后续 UI 维护成本。

## 范围与边界

### 本次范围

- 顶部深蓝导航栏和当前页面选中状态。
- 左侧操作区的 Card 化布局、字体、颜色、间距和按钮层级。
- 右侧 256 通道区域的 16×16 Tile 视觉呈现、行列坐标、状态颜色、Tooltip/详情入口。
- 顶部通道统计：总数、PASS、NG、测试中、空闲及占比。
- 事件日志、探针寿命进度、设备状态和底部状态栏的展示方式。
- 仅刷新发生变化的通道和统计显示，避免新增整页刷新。

### 明确不改动

- OCV/IR 测试流程、启停流程和 NG 复测流程。
- 256 通道编号、行列逻辑和通道选择规则。
- PLC、34465A、3562A、数据库和 MES 通讯。
- 校准算法、NG 判定、测试结果数据结构和数据库字段。
- 现有按钮事件的业务行为：`btnStart_Click`、`btnStop_Click`、`btnNGTest_Click`、`btn_ZeroAdjustment_Click`。

## 当前代码上下文

- 项目为 VB.NET WinForms，目标为 .NET Framework 4.x。
- 首页核心窗体为 `frmTest`，主容器为 `MDIForm`。
- 左侧控件集中在 `frmTest.Designer.vb` 的 `Panel1` 下，现有多个 `GroupBox` 承担功能分组。
- 256 通道当前由 `Pic_Bat` 与 `FreshBat()` 负责绘制和刷新。
- `frmTest.vb` 同时包含 UI、测试状态和部分显示逻辑，因此本次采用渐进式改造，不一次性重写窗体。
- 当前目录不是 Git 仓库，实施过程使用阶段目录备份、编译和运行回归作为保护措施。

## 总体布局

```text
┌──────────────────────────────────────────────────────┐
│ 顶部导航栏 58px                                      │
├───────────────┬──────────────────────────────────────┤
│ 左侧控制区     │ 通道统计区                           │
│ 宽度约370px    ├──────────────────────────────────────┤
│ Card 列表      │ 16×16 256 通道矩阵                   │
│               │                                      │
├───────────────┴──────────────────────────────────────┤
│ 底部设备状态栏 36px                                  │
└──────────────────────────────────────────────────────┘
```

1920×1080 时使用约 370px 左侧区域；其余空间交给统计区和通道矩阵。较小分辨率下保持通道顺序和功能可用，允许通道区缩放或内部滚动，不使用会导致错位的固定整页坐标。

## 页面组成

### 顶部导航

保留现有功能入口：系统设置、测试、查询、校准、MES 上传。顶部使用深蓝背景，当前页面增加 3px 蓝色底部选中条。导航点击继续复用现有逻辑，不新增业务行为。

### 左侧控制区

按以下顺序排列 Card：

1. 工位选择。
2. 托盘与电池信息。
3. 操作按钮。
4. 通道校准。
5. 合格范围。
6. 设备状态。
7. 探针使用统计。
8. 事件日志。
9. 报警复位。

现阶段优先保留原有控件和名称，通过布局与样式完成 Card 化，避免破坏已有事件绑定。

### 操作按钮

- 启动测试：`#1677FF` 背景、白色文字，作为主按钮。
- 停止测试：白底、红色边框、红色图标和文字。
- NG 复测：橙色强调。
- 仪器调零：紫色或中性蓝色。
- 报警复位：白底红色边框，仅在存在报警时高亮。

继续使用现有按钮事件，不修改事件内部流程。

### 通道统计

显示总通道数 256，以及 PASS、NG、测试中、空闲的数量和百分比。统计只读取现有通道数据，公式为数量除以 256，再乘以 100。统计区是展示层，不启动新的采集或测试逻辑。

### 256 通道矩阵

新增纯 UI 职责的 `ChannelGridControl`，负责创建 16×16 Tile、行列坐标、通道编号、状态颜色、Tooltip 和局部更新。它不负责仪器通讯、数据库、MES、NG 判定或测试流程。

Tile 默认只显示通道编号，例如 `12-8`。Tooltip 或详情区域显示条码、OCV、IR、状态和结果，避免 256 个通道长期显示完整测量数据。

状态颜色约定：

| 状态 | 背景 | 文字 |
| --- | --- | --- |
| PASS | `#DCFCE7` | `#15803D` |
| NG | `#FEE2E2` | `#DC2626` |
| 测试中 | `#DBEAFE` | `#2563EB` |
| 等待 | `#FEF3C7` | `#D97706` |
| 空闲 | `#F3F4F6` | `#6B7280` |
| 禁用 | `#E5E7EB` | `#9CA3AF` |
| 通讯/设备故障 | `#FEE2E2` | `#991B1B` |

第一阶段通过 UI 映射将现有测试状态转换为显示状态；不强制修改现有业务数据模型。后续可以再引入统一 `ChannelStatus` 和 `ChannelViewModel`。

### 事件日志与探针寿命

现有日志来源和追加机制保持不变，展示标题改为“事件日志”，视觉上区分 INFO、SUCCESS、WARNING、ERROR。探针统计保留总数、已使用、剩余，增加使用率进度条：低于 80% 为绿色，80%~95% 为黄色，高于 95% 为红色。

### 底部状态栏

统一展示工位、PLC、电压表、内阻仪、数据库、MES、当前用户和时间。连接状态统一使用中文，例如“数据库：已连接”，不改变底层连接判断。

## 数据与刷新设计

第一阶段沿用 `RecieveData` 和现有测试状态作为数据来源，新增 UI 映射层：

```text
现有测试状态/RecieveData
        ↓
GetChannelUiStatus(channel)
        ↓
ChannelGridControl.UpdateTile(channel)
        ↓
统计区同步更新
```

数据变化时只更新变化的 Tile 和统计值。不得以 `Form.Refresh()`、整个 `Panel.Refresh()` 或整张 Bitmap 重绘作为高频测试更新方案。现有 `FreshBat()` 的业务判定和报警副作用在第一阶段不改动，通道绘制迁移采用可验证的小步替换。

## 文件与组件边界

计划逐步增加以下纯 UI 文件，具体文件名以项目现有命名习惯为准：

```text
UiTheme.vb          颜色、字体、间距和控件样式常量
ChannelGridControl.vb 16×16 通道矩阵和局部更新
ChannelTileControl.vb 单个通道 Tile 的绘制、Tooltip 和点击
StatisticsControl.vb 通道统计卡片
BottomStatusControl.vb 底部状态栏展示
```

`frmTest` 保留现有业务事件和测试流程，只负责把现有状态交给显示控件。若第一阶段风险评估认为新增控件过大，可先在原控件结构中完成同等视觉改造，再逐步替换显示层。

## 实施阶段

1. 建立当前版本备份，记录编译、启动和核心流程基线。
2. 增加统一 UI 主题定义。
3. 调整 `MDIForm`、`frmTest` 和 Designer 的主框架布局。
4. 将左侧原有功能区改造成 Card 视觉，并保留控件和事件绑定。
5. 增加通道统计区。
6. 将通道显示改为 16×16 Tile，保持既有编号与数据顺序。
7. 增加 Tooltip、详情入口和状态映射。
8. 增加事件日志样式、探针进度和底部状态栏。
9. 实现局部刷新并进行运行回归。

第二阶段再考虑统一 `ChannelStatus`、`ChannelViewModel`、UI 更新服务以及测试线程与 UI 线程的进一步解耦，本设计不把这些架构重构作为第一阶段上线前置条件。

## 验收标准

- 程序能够正常启动，主界面布局符合顶部导航、左侧控制、右侧矩阵、底部状态栏结构。
- 256 个通道完整显示，行列坐标、通道编号和既有逻辑一致，无错位。
- PASS、NG、测试中和空闲统计数量与通道显示一致。
- 普通测试、停止测试、NG 复测、仪器调零、校准、数据库和 MES 流程行为不变。
- 测试期间 UI 不因整页频繁刷新出现明显闪烁、卡顿或输入失效。
- 通道 Tooltip/详情数据来自现有数据，不引入新的测试或数据库查询流程。
- 1920×1080 下布局完整；较小窗口下无控件重叠，通道区可读且不改变通道顺序。
- 所有颜色、字体和尺寸集中管理，不在各个窗体中散落硬编码。

## 风险控制

- 不修改 `FormalTestRunner`、`CalibrationService`、通讯类、数据库类和 MES 上传类。
- 不修改 `RecieveData` 的业务含义和现有 NG 判定。
- 不删除业务事件依赖的现有控件。
- 不将行优先和列优先的 256 通道映射混用。
- 每完成一个视觉区域就编译并启动检查，再进入下一个区域。
- 在当前无 Git 的目录中，对关键文件和整个项目建立带日期的阶段备份。
