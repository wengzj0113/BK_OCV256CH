# 明文用户密码设计

## 目标

将应用内所有用户账户改为使用明文密码保存和校验，并重置系统管理员与操作员账户。具体账户值由用户在本次会话中提供，不写入设计文档、提交信息或回复正文。

## 当前实现

- `UserAccountStore` 将账户保存到与可执行文件同目录的 `UserData.txt`。
- 新账户默认使用哈希值保存密码。
- 登录时先计算输入密码的哈希，并兼容旧的明文记录；成功匹配旧明文后会自动转换为哈希。
- `bin\\Debug` 与 `bin\\AnyCPU` 可能使用不同的 `UserData.txt`。

## 方案

1. `UserAccountStore.EnsureFile` 创建账户时直接写入明文密码。
2. `Authenticate` 只对账户文件中的密码字段与用户输入做直接比较，不再计算哈希，也不再自动升级密码格式。
3. `AddOrUpdate` 直接保存用户输入的明文密码。
4. 为已有账户提供一次性重置：系统管理员和操作员账户使用用户确认的用户名及密码；账户角色保持不变。
5. 当前部署的账户文件写入用户确认的账户值；为保证账户文件缺失时仍能自动初始化，默认账户值也写入账户存储初始化代码。凭据不写入设计文档、Git 提交或测试输出。
6. 增加回归测试，覆盖明文登录、错误密码拒绝、用户更新后可登录，以及不再生成哈希值。

## 风险与边界

明文账户文件可被能读取应用目录的人员直接查看，安全性低于哈希存储。本次按用户明确要求实施，不扩展到数据库密码、MES 密码或其他外部系统凭据。

## 验收标准

- 两个指定账户可以使用新密码登录。
- 错误密码不能登录。
- 新增或修改用户后，`UserData.txt` 中保存的是明文，而不是 64 位哈希。
- Debug 与 AnyCPU 启动时使用预期的账户文件。
- 项目原有编译和授权测试通过。
