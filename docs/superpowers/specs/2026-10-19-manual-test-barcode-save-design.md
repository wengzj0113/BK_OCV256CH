# 手动测试条码、确认保存与全局按条码更新设计

日期：2026-10-19

## 已确认的需求

1. 独立窗体 `FrmManualTest` 使用方案 A：保留紧凑工具栏，接入用户已添加的托盘码标签、输入框和“获取条码”按钮；补充条码来源状态和结果表的电芯条码列。
2. 根据托盘码查询 OCV_DATA 的电芯条码；没有条码时生成测试条码。
3. 测试结束后询问是否保存到数据库。模拟条码结果只存本地 OCV_DATA，不上传 MES；真实条码在本地保存成功后按现有 MES 结果接口上传。
4. 多轮测试批次结束后确认一次。按轮次依次保存；相同条码覆盖更新，所以数据库最后只保留该条码最后一次成功保存的结果。Excel 保留全部完成轮次；MES 只上传最后一个完成轮次。
5. 所有通过 OCV_DATA 正常结果保存入口写入的结果，都按电芯条码覆盖更新；该规则不限于本次手动测试窗体。
6. 部署脚本不批量清理已有重复结果。只有今后再次保存的条码才合并其旧重复结果，其余旧数据保留。
7. 统一规则放在 OCV_DATA 的保存过程内，覆盖各测试入口；这是用户选择的实现方案 1。

## 现状

- `FrmManualTest` 已有 `Label1`（托盘码）、`TextBox1`、`Button2`（获取条码），尚无对应业务处理。已有通道选择、单次测试、多次测试、CSV 导出及多轮 Excel 输出。
- `OcvDataService.GetTrayCellsByTrayCode` 返回 `ChannelNo` 和 `BatteryCode`；`CreateTestTask`、`SaveTestResults`、`CompleteTestTask` 已封装本地结果写入。
- `usp_SaveTestResults` 当前按 `(TestTaskId, ChannelNo)` 更新，允许同条码在不同任务中重复存在。
- `ResultDataUploadAssembly` 实现现有 MES JSON 接口及失败后写入 UploadOutbox 的行为，但其快照入口读取主窗体和全局变量，不能直接当作独立手动窗体的结果上下文。
- `OCV_RETEST_DATA.SourceTestResultId` 引用原结果编号，合并旧结果时需要维护关联；复测记录本身包含原测和复测数值快照。
- 工作区已有大量未提交修改，包括本次涉及的文件；实现必须在这些修改之上追加，不能还原或覆盖它们。

## 页面与条码准备

- 把用户新增控件命名为 `lblTrayCode`、`txtTrayCode`、`btnGetBarcode`，保留 WinForms Designer 编辑能力。没有行为的占位 `Button1` 从工具栏移除。
- 使用方案 A 的紧凑布局：条码输入及按钮位于工具栏，补充状态文字，显示已加载数量与“数据库/模拟”来源。结果表增加“电芯条码”列，CSV 和多轮 Excel 同步包含条码。
- 扫码枪按键盘方式向托盘输入框输入。回车触发获取条码；获取成功不自动启动测量。
- 获取时先校验托盘码非空、长度符合数据库字段，且没有测试、校准、扫码复测或其他设备操作占用。
- 查询整个托盘的映射，保留标准通道编号，不能把稀疏通道压缩重排。非法通道、重复通道或重复非空电芯码报错。
- 查询成功但无任何有效电芯码时，为 1–256 通道生成模拟条码；模拟条码包含日期、托盘标识摘要及标准通道号，长度不超过 100 字符。同一天、同托盘、同通道重复取码得到同一测试条码，不同托盘不会共享模拟码。
- 如果托盘有部分真实条码，使用已有映射；所选通道中缺码时阻止启动并列出缺码通道，由操作员调整选择。此时不把缺码通道静默补成混合来源结果。
- 数据库连接或查询异常与“查询成功但无条码”区分处理：异常显示查询失败，不生成模拟码掩盖异常。
- 模拟条码只属于本次准备上下文，不注册或覆盖 `TrayCell` 真实托盘映射。
- 输入框中的托盘码变化会使原条码准备失效；再次测试前必须重新获取。调整所选通道后，启动时验证选中通道均有准备好的条码。

## 测试快照与完成交互

- 单次及多次测试沿用 `FormalTestRunner.RunSparseMeasurement` 和现有标准通道到设备通道的映射。
- 启动时固定托盘码、条码映射、所选通道、条码来源、OCV 阶段、操作员和 MES 所需上下文；运行中禁用取码和修改这些数据的控件。
- 每轮完成后立即复制测量数据，包括条码、电压、原始内阻、校准值、最终内阻、判定和采集时间。显示、导出、落库及 MES 均使用该轮快照，不能在下一轮后重读共享测量数组。
- 单次完成后询问是否保存；多次测试结束后对已完成轮次询问一次。中途失败且已有完成轮次时，允许保存已完成部分；没有完成轮次时不询问保存。
- 选择不保存时保留已显示结果和手动导出能力。多轮 Excel 的逐轮落盘行为仍提供完整批次记录。
- 选择保存时，按轮次顺序创建对应任务、保存结果并完成任务。真实条码任务类型为 `Manual`、来源为 `ManualTest`；模拟条码任务及来源为 `Debug`。
- 全部待保存轮次本地保存成功后，真实条码才提交最后完成轮次的 MES 上传；模拟条码不提交 MES，也不进入生产上传队列。
- 保存期间继续锁定启动和关闭，结束或失败时恢复控件。状态文字明确区分测量失败、本地保存失败、上传成功及上传待重试。

## OCV_DATA 全局按条码更新

- 改动集中在 `usp_SaveTestResults`，所有调用它的手动、正式、自动和调试结果保存路径使用同一规则。
- 先规范化输入：去掉条码首尾空白；继续支持从有效 `TrayCell` 补齐省略的条码。规范化后仍为空则拒绝保存，避免无键结果绕过去重规则。
- 同一次输入的通道和非空条码必须各自唯一；同条码对应多个输入通道时拒绝整批写入，并给出条码信息。
- 条码比较遵循 OCV_DATA 字段排序规则。结果身份是电芯条码，不加托盘、通道、测试阶段或任务类型作为去重条件；相同条码在这些字段变化后仍更新到本次上下文。
- 在事务中串行保护统一结果保存过程，保证并发保存同条码时不会产生新的重复行。可使用事务所有者的 `sp_getapplock`；获得锁失败则整批失败并回滚。
- 对每个输入条码，找出全部旧结果。保留最新一条旧结果的 `TestResultId`（按 `COALESCE(UpdatedAt, CreatedAt)`、`TestResultId` 降序确定）；不存在时插入新结果。
- 有旧重复结果时，先把 `OCV_RETEST_DATA.SourceTestResultId` 指向将保留的结果编号，再删除该条码的其他旧结果。复测记录中的原测、复测数值快照保留。
- 更新保留结果的任务、托盘、阶段、通道、测量值、规格上下文、判定及来源到当前结果。保留结果编号及首次创建时间，更新 `UpdatedAt`。如果目标任务通道已有不属于本次输入的其他条码，则报错回滚；同批次条码之间交换通道允许保存。
- 任务记录作为操作记录保留；当某条码被更新到新任务时，旧任务不再拥有该条码的历史结果行。这符合“一条码一条当前结果”的规则。
- 其他未参与本次写入的旧条码重复数据不做清理；部署时不执行全表删除或去重。
- 由于未处理的旧重复数据允许存在，本次不能直接增加全局条码唯一索引。增加条码查询的非唯一索引；把原任务通道唯一索引调整为非唯一查询索引，以支持同批次条码交换通道。由输入校验及统一保存事务保证正常写入规则，索引调整不删除数据。
- NG 扫码复测的独立审计记录继续保存其快照。“覆盖原结果”路径也参加同一保存锁，在源身份校验通过后合并本次条码的旧重复当前结果并维护源编号；只记录复测审计、没有覆盖原结果时，不触发当前结果合并。过期源数据不得覆盖新托盘/新通道的当前结果。
- 同时维护现代安装脚本、SQL Server 2008 R2 安装脚本和可单独运行的现有库升级脚本。升级只更新过程和所需索引，不主动处理历史重复行。

## MES 上传

- 使用现有 `ResultDataUploadAssembly` 接口地址、字段、鉴权配置和 `Return_Code = S` 成功判定。
- 为上传器提供显式快照入口，接收托盘、实际选中标准通道、条码及该轮结果、阶段、操作员、过程号、时间和环境信息；现有主页面调用保留兼容入口。
- 使用既有 MES 结果上传启用设置。未启用或未配置时，仅显示本地保存结果；已启用时提交当前快照。
- MES 临时不可用、HTTP 失败或返回业务失败时，按现有 UploadOutbox 路径保留待上传数据，并显示待重试状态；不能因上传失败重复新增本地测量结果。
- 不通过修改主窗体的托盘码、全局当前托盘或测试阶段来“借用”其上传上下文。

## 模块划分

- `FrmManualTest.Designer.vb`：静态控件、紧凑布局和条码结果列。
- `FrmManualTest.vb`：页面状态、取码操作、测试调用和保存确认；仅协调下列服务。
- 手动测试条码准备模块：校验数据库映射、生成带托盘身份的模拟码、构造固定条码计划。
- 手动测试结果模块：每轮快照、任务与本地结果写入、按条件提交最后一轮上传。
- `ManualTestWorkbookWriter.vb`：工作簿增加条码字段，继续逐轮持久化。
- `ResultDataUploadAssembly.vb`：显式 MES 快照入口与兼容现有调用。
- 数据库过程及迁移：统一条码更新、重复结果合并和复测关联维护。

## 失败处理与验收

1. 真实托盘取码、无条码模拟、部分条码、空输入、非法映射、数据库异常均有明确状态；运行中不能重新取码。
2. 单次测试完成后仅询问一次；选择不保存不写测量结果和 MES 队列。
3. 多轮数据在测量后独立快照；本地依轮次按条码覆盖，最终数据库结果与最后保存轮次一致，Excel 包含全部完成轮次。
4. 同条码重复保存、跨托盘/通道/阶段保存和多入口调用均只保留该次涉及条码的一条当前结果。
5. 未再次保存的旧重复条码原样保留；再次保存的旧重复条码合并后，复测源关联可追溯且没有悬空编号。
6. 重复条码输入及并发竞争不能留下部分合并数据；失败时整个该轮保存事务回滚。
7. 模拟数据只能本地保存为 Debug；真实数据在本地成功后按配置上传最后轮次，失败时可重试。
8. 编译并执行与条码准备、快照隔离、重复覆盖、SQL 兼容性和 MES 载荷相关的定向检查；有数据库环境时验证事务、旧重复合并和并发行为。没有现场连接时明确记录数据库及设备联调限制。

## 设计自审

- 已按用户后补规则明确：全部轮次在 Excel 保留；数据库同条码最终一条，最后一次成功写入覆盖先前轮次。
- 已明确全局覆盖不按阶段、托盘或任务类型保留第二条结果；部署不全量去重。
- 已区分真实条码、模拟码、无记录、部分记录和查询失败，避免混合来源和错误兜底。
- 已覆盖复测源引用、数据库并发及 MES 全局快照耦合，未加入无关设备流程改造。
