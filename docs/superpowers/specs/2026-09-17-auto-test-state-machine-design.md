# 自动测试状态机与 PLC 放行设计

## 1. 目标

重新定义主测试页面的“自动”模式，移除由 `autoStartFlag + Timer4` 直接触发正式测试的旧式电平轮询逻辑，改为以托盘为边界、以状态机推进的自动流程。

自动流程负责：

1. 识别托盘到位；
2. 启动扫码并取得托盘码；
3. 根据托盘码加载各物理通道的电池条码；
4. 校验测试数据和设备条件；
5. 调用 `StarTest(1)` 执行正式测试；
6. 保存本地结果；
7. 通知 PLC 测试完成。

MES 结果上传改为后台任务，不阻塞 PLC 放行和下一托盘流程。NG 复测不再作为自动流程的必经步骤，而作为独立的人工操作。

## 2. 流程边界

### 2.1 上位机负责

- 监听托盘到位信号并进行稳定/边沿判断；
- 启动扫码、接收扫码结果；
- 将托盘码写入主页面 `txtTray`；
- 查询托盘对应的电池条码；
- 按物理通道号加载 `RecieveData(channel - 1).BatCode`；
- 调用正式测试入口 `StarTest(1)`；
- 保存 OCV_DATA 和本地测试文件；
- 将结果加入 MES 后台上传队列；
- 本地结果保存成功后通知 PLC 测试完成；
- 接收并记录 PLC 的完成应答。

### 2.2 PLC 负责

- 提供托盘到位状态；
- 按现场协议提供夹具闭合/测试允许状态；
- 接收上位机的测试完成通知；
- 返回完成应答；
- 在收到完成通知后安排松夹具、托盘流转和下一步工艺动作。

上位机不在测试完成后自行安排 PLC 后续机械动作。

### 2.3 MES 负责

- 接收后台上传的测试结果；
- 返回上传成功或失败结果。

MES 上传失败只影响 MES 上传状态，不阻塞已经完成本地保存的测试流程；失败数据进入本地上传队列并按策略重试。

## 3. 状态机

```text
WaitingTray
    ↓ 托盘到位信号稳定
TrayDetected
    ↓ 启动扫码
Scanning
    ├─ 扫码成功 → ScanSucceeded
    ├─ 扫码超时 → ScanFailed
    └─ 扫码异常 → Error

ScanSucceeded
    ↓ 写入 txtTray，查询电池条码
LoadingCellBarcodes
    ├─ 校验成功 → ReadyToTest
    └─ 查询/校验失败 → LoadFailed

ReadyToTest
    ↓ 最终设备检查通过
Testing
    ├─ 测试成功 → LocalSaving
    └─ 测试失败 → TestFailed

LocalSaving
    ├─ 本地保存成功 → PlcCompletionPending
    └─ 保存失败 → SaveFailed

PlcCompletionPending
    ↓ 发送 TestCompleted
WaitingPlcAck
    ├─ 收到应答 → Completed
    └─ 超时 → PlcNotifyPending

Completed
    ↓ PLC 安排后续动作，托盘离开
WaitingTray
```

MES 上传作为旁路任务运行：

```text
LocalSaved → MesPending → MesUploading → MesUploaded
                                      └→ MesUploadFailed → Retry
```

NG 复测作为独立人工流程运行：

```text
RetestIdle → RetestRunning → RetestSaved → MesPending
```

## 4. 自动流程详细规则

### 4.1 模式选择

- 主页面选择“自动”后进入 `WaitingTray`；
- 自动模式和手动模式互斥；
- `Testing`、`LocalSaving`、`PlcCompletionPending`、`WaitingPlcAck` 状态期间禁止切换模式；
- 自动模式不再由 `autoStartFlag + Timer4` 直接调用 `StarTest(1)`。

### 4.2 托盘到位

托盘到位不能使用单次读取结果直接触发。流程必须：

1. 连续读取 PLC 托盘到位信号；
2. 进行稳定时间或连续采样判断；
3. 只在未到位到已稳定到位的边沿触发一次；
4. 测试处理中忽略新的托盘到位事件；
5. 当前托盘完成并确认离开后，才允许识别下一个托盘。

同一个托盘在未离开前不得重复扫码、重复查询或重复启动测试。

### 4.3 扫码

进入 `Scanning` 后：

- 只允许一个扫码任务；
- 扫码成功后保存当前托盘上下文；
- 托盘码为空、格式非法或超时进入错误状态；
- 扫码失败不得调用 `StarTest(1)`；
- 同一个托盘的重试必须复用当前托盘上下文，不能创建新的测试任务。

### 4.4 电池条码加载

扫码成功后，根据托盘码查询通道和电池条码，并校验：

- 通道号必须在 `1~256`；
- 通道号不能重复；
- 电池条码不能为空；
- 电池条码重复时按业务规则拒绝或报警；
- 查询结果必须和当前托盘码匹配；
- 查询前清除上一托盘的条码数据；
- 查询后按物理通道写入 `RecieveData`；
- 自动模式的测试通道只能来自本次查询成功的有效通道集合。

加载成功后刷新主页面，并锁定本次测试通道集合。

### 4.5 正式测试前最终检查

只有以下条件全部满足时，才允许进入 `Testing`：

- 当前仍为自动模式；
- 当前托盘仍然到位；
- PLC 夹具状态满足测试要求；
- 无报警；
- 中位机通讯正常；
- 测试仪器通讯正常；
- 存在至少一个有效通道；
- 每个待测通道都有电池条码；
- 当前没有其他测试任务；
- 当前托盘尚未启动过测试。

自动模式下这些条件应转换为状态和日志，不使用阻塞式确认框替代校验。

### 4.6 正式测试

测试状态调用现有正式入口：

```vb
StarTest(1)
```

`StarTest(1)` 负责执行通道计划、仪表测量、结果回填和 OK/NG 判定。测试期间：

- 禁止切换自动/手动模式；
- 禁止修改测试通道；
- 禁止重复启动；
- PLC 新托盘事件不触发新的任务。

## 5. 保存、MES 和 PLC 通知顺序

正式测试完成后的顺序定义为：

```text
测量完成
    ↓
生成最终 OK/NG 结果
    ↓
保存 OCV_DATA
    ↓
保存本地测试文件
    ↓
本地保存成功
    ├─ 通知 PLC 测试完成
    └─ 创建 MES 后台上传任务
```

其中：

- 本地文件保存失败时，不通知 PLC；
- OCV_DATA 保存失败时，不通知 PLC；
- MES 上传是否成功不影响 PLC 放行；
- MES 上传任务必须带有托盘码、测试任务号和幂等键；
- MES 上传失败时记录失败原因并后台重试；
- MES 上传状态与 PLC 流程状态分开管理。

当前 `ResultDataUploadAssembly.StartTimer()` 是一次性启动后台上传，不代表上传成功。后续实现需要提供可确认的后台任务状态，但不能让主测试线程等待 MES 网络请求。

## 6. PLC 完成通知

本地保存成功后发送 `TestCompleted` 通知，建议携带：

- 托盘条码；
- OCV_DATA 测试任务号；
- 测试结果；
- 有效通道数；
- 完成时间；
- 唯一幂等键。

建议采用握手：

```text
PC → PLC：TestCompleted
PLC → PC：TestCompletedAck
```

通知成功的定义是 PLC 已确认收到，而不是 PC 成功执行了一次发送函数。

如果 PLC 应答超时：

- 不重新执行测量；
- 使用相同的任务号和幂等键重发通知；
- 记录 `PlcNotifyPending`；
- 等待 PLC 应答或进入人工处理状态。

PLC 收到完成通知后负责安排下一步，PC 进入等待托盘离开或等待 PLC 状态变化的状态。

## 7. 独立复测规则

复测不阻塞自动主流程：

- 正式测试完成并通知 PLC 后，自动周期可以结束；
- 操作员可单独选择 NG 通道启动复测；
- 复测使用 `StarTest(0)`；
- 复测仍需检查设备和当前测试锁；
- 复测结果单独保存并进入 MES 后台上传；
- 复测不得重新触发 PLC 的托盘流转流程；
- 复测不能与新的正式测试并发执行。

如果业务要求复测结果覆盖正式结果，必须另行定义 MES 修正接口和结果版本规则；默认不覆盖 PLC 已经使用的正式测试完成状态。

## 8. 异常恢复

| 异常 | 处理方式 |
|---|---|
| 托盘不到位 | 保持 `WaitingTray` |
| 扫码超时 | 进入 `ScanFailed`，允许同托盘重试 |
| 托盘码非法 | 不查询、不测试，记录错误 |
| 条码查询失败 | 进入 `LoadFailed`，不调用 `StarTest(1)` |
| 条码缺失或重复 | 阻止测试，提示具体通道 |
| 设备报警 | 停止启动或中止当前流程，等待复位 |
| 测量失败 | 保存失败状态，不通知 PLC 完成 |
| 本地保存失败 | 不通知 PLC，允许人工重试保存 |
| MES 上传失败 | 不阻塞 PLC，后台重试 |
| PLC 完成应答超时 | 不重测，使用相同任务号重发通知 |
| 程序异常退出 | 根据 OCV_DATA 任务状态和 PLC 状态恢复待处理任务 |

## 9. 验收标准

1. 自动模式只能由托盘到位事件启动流程；
2. 同一个托盘只扫码、查询和正式测试一次；
3. 扫码失败或条码加载失败时绝不调用 `StarTest(1)`；
4. 本地结果保存成功后可以通知 PLC；
5. MES 上传过程不阻塞 PLC 完成通知和下一托盘流程；
6. MES 上传失败会进入后台重试队列；
7. PLC 完成通知具备幂等性和应答超时处理；
8. PLC 收到完成通知后由 PLC 负责下一步动作；
9. NG 复测可以单独启动，不阻塞自动主流程；
10. 复测不会重复触发 PLC 托盘流转；
11. 自动流程、MES 上传和复测状态在界面及日志中可区分显示。

## 10. 待确认的外部接口

实现前需要确认 PLC 和扫码器协议：

- PLC 托盘到位地址；
- PLC 夹具闭合/测试允许地址；
- PLC 测试完成通知地址或命令；
- PLC 完成应答地址或命令；
- 通知数据中的托盘码、任务号和结果编码；
- 扫码启动命令、扫码成功信号、扫码超时时间；
- PLC 和扫码器的重试、复位及断线恢复规则。
