# 响应式测试界面设计规格

## 目标

将测试主界面从依赖 Designer 初始 `Location/Size` 的固定布局，调整为响应式布局，消除右侧大面积留白，并参考图片 2 的卡片化信息层级。界面必须能随屏幕尺寸和 DPI 变化，窄屏时左侧控制区整体滚动，右侧矩阵仍保持可用且不被底部状态栏遮挡。

## 当前问题

- `frmTest` 的左、右控件直接放在窗体上，右侧控件以固定设计尺寸起步，实际 MDI 客户区变宽后会出现未被布局容器管理的留白。
- `statisticsControl` 固定高度为 96，`channelGrid` 依赖 Designer 的初始宽高和四边锚定，统计区与矩阵没有形成统一的右侧布局流。
- 右侧统计信息、图例和矩阵没有按参考图形成清晰的卡片层级。
- 窄屏时左侧控制区与右侧内容缺少明确的自适应边界。

## 设计

### 1. 主体布局

在 `frmTest` 中建立响应式主布局容器：

- 根容器使用 `Dock = Fill`，不再依赖窗体的固定初始宽度。
- 第一列承载左侧控制区，宽度使用布局比例/最小可用宽度计算；左侧 `Panel1` 保持 `AutoScroll = True`，窄屏时由它整体滚动。
- 第二列承载右侧内容，使用 `Dock = Fill` 占据所有剩余宽度，不设置固定右侧宽度。
- 根容器只负责区域分配，业务控件事件和数据流不改变。

### 2. 右侧卡片结构

右侧使用垂直布局流：

- 顶部统计卡片组包含通道总数、PASS、NG、测试中、空闲和图例。
- 统计卡片组内部使用百分比列；当宽度不足时允许内容在卡片内部重新排列，不能把右侧整体撑出屏幕。
- 下方矩阵卡片使用 `Dock = Fill` 占据统计卡片之外的全部高度和宽度。
- 矩阵标题、列标题、行标题和 16×16 单元格继续由 `ChannelGridControl` 管理，单元格使用百分比行列，不设置固定像素最小尺寸。

### 3. 尺寸与 DPI

- 删除右侧区域依赖 Designer 初始尺寸的固定 `Size` 和 `Location`。
- 不使用固定像素作为响应式断点；布局由 `TableLayoutPanel` 的 Percent/AutoSize、`Dock`、`Anchor` 和 `AutoScroll` 完成。
- 仅保留字体、边框和必要内边距的系统 DPI 缩放，不用固定像素推导主区域尺寸。
- MDI 客户区继续避开底部状态栏，状态栏不得覆盖矩阵内容。

### 4. 小屏行为

- 左侧控制区整体出现垂直滚动条。
- 右侧仍填充可用区域；矩阵的 16 行和 16 列都必须存在，单元格内容不可被截断。
- 不通过压缩字体或隐藏业务控件来“解决”空间不足。

## 涉及文件

- `frmTest.vb`：创建和维护响应式主布局容器，保留事件绑定和业务逻辑。
- `frmTest.Designer.vb`：移除会与响应式容器冲突的右侧固定布局属性，保留控件声明。
- `StatisticsControl.vb`：移除固定高度依赖，使统计卡片随父容器布局。
- `ChannelGridControl.vb`：确保矩阵在父容器提供的空间内按比例布局。
- `ChannelTileControl.vb`：保持无固定最小尺寸、禁止文本自动换行，避免撑高矩阵行。
- `MDIForm.vb`：保留状态栏占位逻辑，确保 MDI 客户区不覆盖底部内容。

## 验证标准

- 右侧内容横向占满 MDI 客户区剩余空间，无大面积空白。
- 统计卡片与矩阵卡片在窗口放大、还原、缩放和不同 DPI 下保持布局关系。
- 窄屏时左侧可滚动，右侧矩阵仍可见；16×16 矩阵无行列被裁切。
- 底部状态栏独立占位，不覆盖矩阵。
- 原有测试、校准、通道点击、Tooltip 和状态更新逻辑不改变。
