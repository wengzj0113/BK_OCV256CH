# 手动测试多次执行与合并 CSV 设计

## 目标

在手动测试窗体增加重复次数选择和“多次测试”按钮。用户可以对当前选择的通道连续执行多轮测试，并将整批结果写入一个 CSV 文件。批次成功或因错误停止后，自动打开已生成的 CSV，方便立即检查数据。

## 用户界面

- 在 `FrmManualTest` 底部区域增加“重复次数”数值选择控件和“多次测试”按钮；重复次数默认为 10，允许范围为 1–1000。
- 保留当前“开始测试”单次测试入口及“导出CSV”功能，互不替代。
- 点击多次测试时，使用启动批次时选定的通道集合和重复次数。运行期间禁用通道选择、夹具操作和其他会干扰本批次的测试操作，并在状态栏显示当前轮次/总轮数。
- 结果表格展示最近一次已完成测试的数据；完整批次结果以 CSV 为准。

## 执行与数据流

- 多次测试复用现有 `FormalTestRunner` 单轮测量流程，按轮顺序执行，避免为手动测试引入第二套仪器控制逻辑。
- 每轮完成后立即读取并快照该轮结果，避免后续测量覆盖全局 `RecieveData` 中的数据。
- CSV 文件在批次启动时创建于应用 `testData` 目录，文件名包含 `ManualTest_Multi` 和时间戳。
- 一个 CSV 保存一个批次；每条记录代表某一轮的一个通道。列包括测试轮次、采集时间、通道、分组、电压（mV）、内阻（mΩ）和判定。字段按 CSV 规则转义，使用 UTF-8 BOM 以兼容常见 Windows 表格软件。
- 每轮结果写入后刷新文件，确保后续轮次失败时已完成轮次的数据仍保留。
- 全部轮次完成后关闭文件并自动打开 CSV。若中途某轮失败，则停止后续轮次，保留并关闭含已完成轮次的 CSV，然后自动打开该文件，并提示失败轮次及错误信息。若第一轮即失败而 CSV 没有数据，也提示失败，不尝试打开空文件。
- 用户通过窗体现有关闭路径或单次测试路径执行时，不改变其现有行为。

## 错误和状态处理

- 运行开始前检查与单次测试一致的权限、PLC、选择通道和设备状态前置条件；整个批次只执行必要的批次级检查，单轮仪器流程仍由现有 runner 负责。
- 批次运行期间防止重复点击启动，并在成功、失败或异常退出的所有路径恢复控件状态。
- 自动打开文件失败时保留 CSV，并明确显示文件路径和打开错误，不影响已采集结果。

## 验收标准

1. 可选择重复次数，默认值为 10，且不能设为 0。
2. 多次测试对批次开始时的同一组通道顺序执行所选轮数。
3. 10 轮数据合并在一个时间戳命名的 CSV 中，每个轮次、每个通道的结果可区分。
4. 每轮完成后数据已持久化；中途失败时先前完成轮次仍可读取，失败后不会继续执行。
5. 批次结束或发生部分失败后，非空 CSV 自动打开；结果表格显示最近完成轮次。
6. 单次测试和现有手动导出功能保持可用。

## 范围

本次只涉及手动测试窗体及其批次 CSV 写入/打开逻辑，不调整仪器初始化参数、自动测试流程、仪器驱动命令或单轮测量算法。
