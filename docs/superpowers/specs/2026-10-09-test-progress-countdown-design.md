# 测试进度倒计时与进度条设计

## 目标

让测试进度窗口中的剩余时间和进度条按同一条 90 秒时间基准推进，避免当前依据阶段百分比推算剩余时间造成不真实的长倒计时，也避免通道数和手动阶段百分比混合导致进度条与实际观感不一致。

## 当前行为

`TestProgressState` 根据已用时间和当前 `_progressPercent` 外推剩余时间。阶段百分比由测试流程传入，通道进度则由 `Advance` 更新；二者混用，因此估算结果会受阶段跳转影响。`frmTestProgress` 按快照显示这两个值，`frmTest` 中的 UI 计时器定期生成快照。

## 设计

- 固定预计测试总时长为 90 秒。
- 测试开始后，剩余时间为 `max(0, 90 秒 - 已用时间)`，以整秒显示并每次快照刷新时更新。
- 测试开始后，时间进度为 `floor(已用秒数 / 90 × 100)`，最多为 99%。以此让倒计时和进度条始终互相对应。
- 只有真实测试完成时，进度才设为 100%；此时剩余时间不再显示倒计时，沿用终态的 `--`。
- 测试超过 90 秒仍未完成时，剩余时间保持 00:00，进度保持 99%，直到完成、失败或取消。
- 保留真实通道完成数、当前通道、阶段、消息、日志以及完成/失败/取消语义；不改测试或仪器执行流程。
- 未开始时保持 0% 和 `--`。失败或取消时停止倒计时，并保留截至终止时刻的时间进度；成功完成时为 100%。

## 实现范围

- 修改 `TestProgressState.vb`：以开始时间和 90 秒常量推导运行中百分比和剩余时间；终态按真实状态处理。
- 检查 `frmTestProgress.vb` 和 `frmTest.vb`：确认现有快照呈现和定时刷新即可反映推导值；除非发现必要适配，不改窗体布局或测试流程。

## 验收条件

1. 测试刚开始时，页面显示约 01:30 剩余且进度为 0%。
2. 运行 45 秒时，剩余时间约 00:45 且进度约 50%。
3. 运行达到 90 秒仍未结束时，页面显示 00:00 和最多 99%。
4. 实际成功完成时，页面显示 100%，剩余时间显示 `--`。
5. 失败或取消后倒计时不再继续；通道计数和阶段信息仍显示快照中的实际值。
