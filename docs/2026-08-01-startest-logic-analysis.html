StarTest(testType) 详细逻辑分析报告

文件：frmTest.vb；方法：Public Function StarTest(ByVal testType As Integer)；分析日期：2026-08-01。

1. 方法定位

StarTest(testType) 是当前测试窗体的正式测试入口。它不是单纯的“启动测量”函数，而是一个大型流程编排函数， 同时负责测试前检查、托盘/夹具动作、调用正式测试 Runner、刷新界面、OK/NG 判定、本地保存、MES 上传、数据库写入，以及 NG 复测触发。

参数含义
testType = 1正常测试。按 frmInput.txtFirst 到 frmInput.txtLast 的连续通道范围测试。
testType = 0NG 复测。按全局 retestArray 中标记为 1 的通道测试。
当前方法虽然声明为 Function，但业务上主要以 Call StarTest(...) 方式调用，返回值没有被上层使用。 目前返回值只是为了满足函数签名，不能代表真实测试成功/失败状态。

2. 调用入口

入口行为
开始按钮 CmdStart_Click先检查报警状态，再调用 StarTest(1)。
自动启动逻辑当检测到自动启动条件且 isRuning = False 时调用 StarTest(1)。
NG 复测确认正常测试后如果 haveNgPoint = True，用户确认后递归调用 StarTest(0)。

3. 顶层流程概览

  1. 初始化返回值、局部变量和 MES 上传对象。
  2. 清空报警显示、刷新电池界面和主窗体测试状态。
  3. 设置 isRuning = True。
  4. 确保托盘号存在于数据库托盘表中。
  5. 读取起始通道、结束通道、总测试数量。
  6. 正常测试时清空 RecieveData 的电压、内阻和测试时间。
  7. 检查托盘号为空或重复托盘号。
  8. 判断本次是 OCV1、OCV2 或 OCV3，并在首次测试时弹窗确认。
  9. 检查中位机串口通讯。
  10. 查询托盘状态，下压夹具，等待约 9 秒，再确认托盘闭合。
  11. 探针使用次数加 1，并刷新剩余寿命显示。
  12. 禁用托盘控制按钮，调用 FormalTestRunner 执行正式测试。
  13. 刷新界面，松开托盘，写运行日志。
  14. 按电压/内阻上下限判定 OK/NG。
  15. 保存本地测试文件，按勾选状态启动 MES 上传。
  16. 写入或更新数据库。
  17. 如果存在 NG 点，询问是否执行 NG 复测。
  18. 统一退出：恢复按钮、鼠标状态和 isRuning = False。

4. 前置检查与状态初始化

4.1 UI 与运行状态

方法开始后会清空 txtAlarm，刷新 Pic_Bat、frmMDI.status_test 和 frmMDI.txtTesting。 随后设置 isRuning = True，表示系统进入测试状态。

4.2 托盘号处理

方法会读取 txtTray.Text 作为托盘号，并检查：

  • 如果托盘号为空，提示用户完成扫码，并打开 frmInput。
  • 如果托盘号与上次相同，弹窗询问是否继续，避免重复误测。
  • 如果托盘号不在数据库托盘表中，先调用 InsertTrayNum 插入。
注意：当前代码在检查托盘号为空之前，已经执行了 db.IsExists(txtTray.Text) 和可能的插入逻辑。 如果 txtTray.Text 为空，理论上存在向托盘表插入空托盘号的风险，应在后续重构中把托盘号校验前移。

5. OCV 次数判定

方法通过 Rbtn1、Rbtn2、Rbtn3 判断本次是 OCV1、OCV2 或 OCV3。 如果没有选择，则提示“请选择OCV！”并退出。

如果全局 isAskOcvNum = False，会弹窗要求确认当前 OCV 次数。用户取消时直接 Exit Function。

这里的 Exit Function 不经过 exit_sub 标签，因此不会执行尾部统一恢复逻辑。 目前它发生在禁用托盘按钮之前，实际影响较小，但从结构上看仍不统一。

6. 中位机通讯与夹具动作

正式测试前先调用 CheckCom_SCM() 检查中位机串口通讯。当前实现使用 RS485 串口，参数来源于初始化配置中的 SCMComPort 和 SCMComRate。

通讯成功后，方法仍会调用旧夹具相关逻辑：

  • GetSignalTrayStatus() 查询托盘/夹具状态。
  • mSock.GetSignalFixtureDown 获取下压夹具指令。
  • socketSR(temp) 发送旧 socket 指令。
  • 等待 Sleep(9000)。
  • 再次查询托盘状态，若 fixtureClose = False，提示托盘未闭合并退出。
根据前面确认，夹具后续会由 PLC 实现。目前这段仍是旧逻辑，属于暂时保留区域。

7. 探针寿命计数

夹具闭合确认后，方法会把 Initsetting.ProbeUsedCount 加 1，并刷新 txtUsed 和 txtRemain。 如果剩余次数为 0，会弹窗提示更换探针。

当前探针计数发生在正式测试前。一旦后续仪表或中位机测试失败，本次探针使用次数仍已增加。 这可能是合理的，因为夹具已经下压；但应在工艺层面确认“下压即计数”还是“测试成功才计数”。

8. 正式测量子流程

StarTest 自身不直接下发通道计划，也不直接读取 3562/34461 缓存，而是委托给 FormalTestRunner： 

If testType = 0 Then
    formalRunner.RunRetestMeasurement(retestArray)
Else
    formalRunner.RunRangeMeasurement(firstCellNumToTest, lastCellNumToTest)
End If

8.1 正常测试

RunRangeMeasurement(start, end) 根据起止通道构造连续通道列表，底层再拆分为 G1/G2。

8.2 NG 复测

RunRetestMeasurement(retestArray) 扫描 retestArray，把值为 1 的位置转换为物理通道号，再构造零星通道列表。

8.3 Runner 内部顺序

  1. 记录中位机计划日志。
  2. 清空 3562 和 34461 的缓存。
  3. 让 3562 进入外部触发缓存状态。
  4. 让 34461 进入外部触发等待状态。
  5. 中位机执行通道计划并 START。
  6. 中位机完成后，一次性读取 3562 缓存。
  7. 一次性读取 34461 缓存。
  8. TwoPassResultMapper 按选择通道和两遍规则把内阻、电压回填到 RecieveData。
  9. 异常时 STOP、清列表、清仪表缓存，并把异常抛回 StarTest。
这符合已确定的新逻辑：中位机只负责通道计划和 START；实际测量值仍由上位机读取 3562/34461 缓存并回填。

9. 测试后处理

9.1 界面刷新与松开托盘

测试完成后调用 FreshBat(1, firstCellNumToTest, totalCellNumToTest, RecieveData, testType) 刷新电池界面。 随后设置主界面文字为“测试结束”，调用 TrayOpen() 松开托盘，并等待 2 秒。

9.2 OK/NG 判定

正常测试时，遍历 firstCellNumToTest ~ lastCellNumToTest；NG 复测时，只遍历 retestArray(j) = 1 的通道。 每个通道调用 IsNG(voltage, resistance)：

  • 返回 0：OK。
  • 返回 1：电压 NG。
  • 返回 2：内阻 NG。

9.3 本地保存

调用 SaveTestDataLocalFile(RecieveData) 保存本地 CSV/测试数据。当前保存逻辑按 256 通道数组生成输出数据。

9.4 MES 上传

如果 FrmMesTask.chkResultDataUploadAssembly.Checked 被勾选，则停止并启动 ResultDataUploadAssembly 定时器， 由上传模块处理 MES 结果上传。

9.5 数据库写入

方法连接数据库后遍历正常测试范围内的通道，按条码和托盘号查询是否已有记录：

  • 已有记录：调用 Ups4BarCode 更新。
  • 无记录：调用 Ins4BarCode 插入。
当前数据库写入始终遍历 firstCellNumToTest ~ lastCellNumToTest。 如果本次是 NG 复测，前面的 OK/NG 判定只处理复测点，但数据库写入仍可能覆盖整个连续范围。 这与“NG 复测只覆盖 NG 点”的目标存在潜在不一致，应在后续重构中重点处理。

10. NG 复测机制

FreshBat 在刷新显示时会根据 IsNG 设置 haveNgPoint = True，并把 NG 通道对应的 retestArray(index) 标记为 1。StarTest 测试结束后，如果 haveNgPoint = True， 会弹窗询问是否执行 NG 复测。

用户确认后： 

haveNgPoint = False
Call StarTest(0)
这里是递归调用。虽然一般只会递归一层或少量层，但从结构上看，测试流程再次进入同一个大型函数， 状态恢复、按钮启用、数据库写入范围、复测数组生命周期都比较难追踪。

11. 异常和退出路径

位置处理方式说明
托盘号为空/重复取消/未选 OCV/通讯失败/托盘未闭合GoTo exit_sub会执行尾部恢复按钮和状态。
OCV 确认弹窗取消Exit Function不会经过 exit_sub；目前发生较早，风险较低但结构不统一。
正式测试异常记录到 txtAlarm，弹窗，然后 GoTo exit_subRunner 内部会尝试 STOP、清列表、清缓存。
刷新/保存/上传/数据库异常记录到 txtAlarm 并弹窗Catch 后仍继续执行后续状态清理。

12. 当前主要风险点

风险说明建议
职责过重 StarTest 同时处理 UI、设备、测量、保存、上传、数据库、复测。 拆成测试前校验、夹具动作、正式测量、结果处理、持久化、复测决策。
返回值无业务意义 方法是 Function，但调用方基本不用返回值，当前固定返回 0。 后续设计 TestRunResult，明确成功、取消、失败、异常原因。
NG 复测数据库覆盖范围 复测判定按 retestArray，但数据库写入按连续范围。 复测时只保存/更新复测通道，或明确覆盖策略。
旧夹具控制仍在正式流程中 中位机新 RS485 流程已接入，但夹具仍通过旧 mSock/socketSR。 等 PLC 方案确定后，把夹具控制从正式测量流程中抽象出来。
退出路径不统一 多数失败走 GoTo exit_sub，少量路径直接 Exit Function。 统一为结构化 Try/Finally，确保状态恢复一定执行。
托盘号校验顺序偏晚 当前先做数据库存在性处理，再检查托盘号是否为空。 把托盘号空值、重复确认前移到所有数据库操作之前。

13. 建议重构方向

  1. 新增 TestRunResult，让 StarTest 真正返回测试结果状态。
  2. 把托盘号、OCV、通道范围、中位机通讯检查提取为 ValidateBeforeTest()。
  3. 把夹具动作提取为 FixtureController，后续便于切换 PLC。
  4. 保留 FormalTestRunner 作为正式测量核心，避免测量细节回流到窗体代码。
  5. 新增 TestResultPersistence，统一处理本地文件、MES 上传触发和数据库写入。
  6. 把 NG 复测改为外层循环或状态机，避免递归调用 StarTest(0)。

14. 结论

当前 StarTest(testType) 已经接入新的 RS485 正式测量链路：通道计划与 START 由中位机执行，3562/34461 缓存由上位机读取， 并通过 TwoPassResultMapper 回填 RecieveData。这是正确方向。

但 StarTest 仍是一个历史包袱较重的“大流程函数”。它最需要后续处理的不是局部修补，而是把“测试运行状态”和“结果持久化范围” 这两个关键点设计清楚，尤其是 NG 复测覆盖规则、数据库写入范围和退出状态恢复。
