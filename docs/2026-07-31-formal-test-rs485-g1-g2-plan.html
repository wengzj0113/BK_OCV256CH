正式测试流程迁移优化方案 - RS485 G1/G2 256CH

目标：将当前正式测试流程从旧 mSock / SocketCtrolCmd / TCP 中位机控制，迁移到新的 RS485 串口 + G1/G2 双组 + 256 通道 + 仪表缓存一次性读取 架构。

核心原则：中位机只负责通道计划和 START；3562 与 34461 都在测试过程中缓存本次全部测试值；上位机在完成事件后一次性读取缓存，并按 ExecutionOrder 回填到物理通道。

技术栈：VB.NET WinForms、.NET Framework 4.8、System.IO.Ports.SerialPort、3562、34461、CRC16-Modbus、Visual Studio MSBuild。

一、当前问题

问题当前表现目标状态
中位机通讯 正式测试仍大量使用 mSock、SocketCtrolCmd、TCP/IP。 统一改为 SerialMiddleMachineClient，使用 RS485 115200 8N1。
仪表选择 仍调用 IOCardSetAcirOrOcv("ACIR")、IOCardSetAcirOrOcv("OCV") 以及中位机“选择 ACIR/OCV”指令。 正式测试删除这些调用。中位机不再负责仪表选择，只负责通道计划和 START。
通道规模 保存、刷新、复测局部逻辑仍有 64 通道痕迹，例如 testData(63)、ReDim retestArray(63)。 统一使用 256 通道，数组长度以 CalibrationService.ChannelCount 或 MAX_CHANNEL 为准。
读数方式 ACIR 与 OCV 是两段旧流程，中位机分别切换，读数回填逻辑分散。 3562 和 34461 同步进入外部触发缓存模式，中位机执行计划后，上位机一次性读取两台仪表缓存。

二、目标测试流程

  1. 点击开始测试。
  2. 检查报警状态；如果报警中，禁止测试。
  3. 初始化测试状态：清空报警、设置 isRuning=True、读取起始/结束通道、初始化 256 通道 RecieveData、检查托盘号。
  4. 判断本次测试为 OCV0 / OCV1 / OCV2。
  5. 检查中位机串口通讯：RS485、115200、8N1。
  6. 夹具动作：查询托盘状态、下压夹具、等待约 9 秒、确认闭合。此部分未来接 PLC，本轮先做边界封装，避免继续依赖中位机旧 TCP。
  7. 探针寿命计数加 1。
  8. 配置 3562：外部触发、连续初始化、清空缓存、打开缓存。
  9. 配置 34461：外部触发、触发次数等于本次测试通道数，准备缓存电压。
  10. 生成中位机通道计划：
    • 正常连续测试：firstCellNumToTest ~ lastCellNumToTest。
    • 正常零星测试：按用户选择通道列表。
    • NG 复测：按 retestArray 中为 1 的通道。
  11. 中位机执行 G1/G2 通道计划并 START。
  12. 等待中位机完成事件 AA 41 00 40 00 06 A5 C8；异常事件 0x0064 立即中止。
  13. 读取 3562 缓存，取得内阻数据。
  14. 读取 34461 缓存，取得电压数据。
  15. 按 ExecutionOrder 回填： 
    RecieveData(ch).Resistance = measuredResistance + calibrateValueArray(ch)
RecieveData(ch).Voltage = measuredVoltage
  16. 刷新 256 通道界面。
  17. 测试结束后松开托盘。
  18. 调用 IsNG(voltage, resistance) 判断 OK/NG，并写入 retestArray。
  19. 保存本地 CSV：D:\OcvTestData\日期\托盘号.csv。
  20. 如 MES 上传勾选，则启动结果上传。
  21. 写数据库：已有记录更新，没有记录插入。
  22. 如果有 NG 点，询问是否复测；确认后调用 StarTest(0)，按 retestArray 生成零星通道计划。

四、实施计划

Task 1：抽取通道计划服务

  • 新增 TestChannelPlanService.vb。
  • 提供 BuildRangePlan(startChannel, endChannel)。
  • 提供 BuildSparsePlan(channelNumbers)。
  • 提供 BuildRetestPlan(retestArray)。
  • 输出 MiddleMachineChannelPlan，其中 ExecutionOrder 使用物理通道号。
Public Class TestChannelPlanService
    Public Function BuildRangePlan(startChannel As Integer, endChannel As Integer) As MiddleMachineChannelPlan
        Dim channels As New List(Of Integer)()
        For ch As Integer = startChannel To endChannel
            channels.Add(ch)
        Next
        Return BuildSparsePlan(channels)
    End Function

    Public Function BuildRetestPlan(retestFlags As Int16()) As MiddleMachineChannelPlan
        Dim channels As New List(Of Integer)()
        For i As Integer = 0 To Math.Min(retestFlags.Length, CalibrationService.ChannelCount) - 1
            If retestFlags(i) = 1 Then channels.Add(i + 1)
        Next
        Return BuildSparsePlan(channels)
    End Function
End Class

Task 2：新增正式测试执行器

  • 新增 FormalTestRunner.vb。
  • 注入或持有 SerialMiddleMachineClient。
  • 提供 RunMeasurement(plan)：配置仪表、运行中位机计划、读取缓存、返回结果集合。
  • 结果类型包含：物理通道号、电压、内阻、测试时间。
Public Class FormalTestResult
    Public Property ChannelIndex0 As Integer
    Public Property Voltage As Single

    Public Property TestTime As DateTime
End Class

Task 3：3562 缓存读取统一化

  • 正式测试停止使用旧 Trans_BatchReadData_3561 作为主路径。
  • 使用 Trans_ReadCachedData_3562(expectedCount, voltages, resistances)。
  • 按 ExecutionOrder 回填，不再依赖仪表返回的局部序号。
  • 回填时叠加 calibrateValueArray(channelIndex0)。

Task 4：34461 批量缓存读取

  • 新增 Trans_ReadCachedData_34461(expectedCount, voltages)。
  • 配置 34461 外部触发、触发次数、等待缓存完成。
  • 返回电压列表，数量必须不少于 expectedCount。
  • 如果实机确认 34461 使用 READ? 阻塞返回数组，则封装在该函数中；如果使用其他内存查询命令，以实机命令为准。

Task 5：重构 frmTest.StarTest

  • 保留报警检查、托盘号检查、OCV0/1/2 判断、探针计数、保存和数据库逻辑。
  • 删除旧 frmDebug.mSock 通讯检查。
  • 删除 IOCardSetAcirOrOcv("ACIR") 和 IOCardSetAcirOrOcv("OCV")。
  • 删除 SendSignalSellectInstrumentType。
  • 删除 GetSignalSelectMutiChannel、GetSignalSelectMutiChannelNG、GetSignalMutiChannelTestFinish 主流程依赖。
  • 改为调用 FormalTestRunner.RunMeasurement(plan)。

Task 6：夹具动作隔离

  • 新增 FixtureController.vb 或在 frmTest 中先封装 CloseFixtureForTest()、OpenFixtureAfterTest()。
  • 本轮不再通过中位机旧 TCP 发送夹具动作。
  • 如果 PLC 尚未接入，函数可保留明确提示或临时复用现有动作，但必须集中隔离，便于后续替换。

Task 7：256 通道数据保存与刷新

  • 将 SaveTestDataLocalFile 中 testData(63) 改为 testData(CalibrationService.ChannelCount - 1)。
  • 所有 For i = 0 To 63 改为 0 到 255。
  • FreshBat 中 ReDim retestArray(63) 改为 255。
  • 确认 UI 仍按当前布局显示；如果当前界面只能显示 64 点，需要另做 256 通道展示方案。

Task 8：OCV0/OCV1/OCV2 UI 与数据字段

  • 确认当前 Rbtn1/Rbtn2/Rbtn3/Rbtn4 如何映射到 OCV0/OCV1/OCV2。
  • 删除或停用 OCV3/OCV4 入口。
  • 数据库写入 intOCV 使用 0/1/2。
  • CSV 字段名称按现场要求调整为 OCV0/OCV1/OCV2。

Task 9：日志与可追溯

  • 沿用 logFile/MiddleMachine_yyyyMMdd.log 记录通道计划、写帧、回显、读寄存器、完成事件。
  • 新增正式测试日志：托盘号、OCV序号、计划摘要、期望读数数量、3562实际数量、34461实际数量。
  • NG复测时记录 retestArray 转换出的物理通道列表。

七、风险点

  • 34461 原始缓存命令需要实机确认。 当前旧逻辑用 READ? + ReadList，是否满足“测试后读取内存缓存”需要现场验证。
  • 夹具动作未接 PLC 前存在实现空窗。 需要决定本轮是临时保留旧夹具动作，还是先封装为空/提示。
  • 界面布局可能仍按 64 通道设计。 数据层可先升 256，显示层可能需要单独优化。
  • 两遍模式数据数量。 如果中位机两遍模式导致仪表每通道两条数据，需要确认正式测试取第几遍、是否做均值或只取最终遍。
  • G2 单组使能值。 当前实现仅 G2 时用 0x006A=0x0002，如实机要求两组使能必须为 3，需要一处调整。

八、执行顺序建议

  1. 先做 Task 1、2：抽出计划服务和正式测试执行器。
  2. 再做 Task 3、4：3562/34461 缓存读取统一。
  3. 再改 Task 5：替换 StarTest 主流程。
  4. 随后做 Task 7、8：256 通道保存、刷新、OCV0/1/2 映射。
  5. 最后做 Task 9 和实机验收。
